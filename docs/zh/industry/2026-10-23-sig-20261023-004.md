# 动作后读过，不等于读回了写入：一次验证评分函数的边界实验

一次写入之后，读取另一个对象，也能在被测评分函数中得到满额确认。这是本轮内部隔离实验的结果，不是已确认的原生系统事故。它提出的问题很具体：一个“写后确认”分数，究竟检查了时间先后，还是检查了同一写入的效果？

## 十个场景检验的是哪一层

本轮分析从固定版本的 MedHarnessBench（医疗智能体运行框架评测）源码中提取未改动的辅助函数，用构造的语义事件执行十个场景。固定版本为 `1b64350432708adfe26db60910db863ac782381d`；这项内部实验绕过原始轨迹适配器、模型和完整评分管线，没有重跑论文基准。

被测的 `_postcondition_confirmation`（后置条件确认函数）先判断任务是否要求改变状态，再遍历成功提交，寻找其后的成功读取或核验事件。判据接受进展标记，或者非空的状态变化字段。它在这一层没有比较主体、资源或提交标识。[固定版本评分源码](https://github.com/Tomry1114/Awesome-Agent-Harness-for-Healthcare/blob/1b64350432708adfe26db60910db863ac782381d/runner/scorers/dim_verification.py)

下表全部是本次内部实验观测，分数只属于这个辅助函数，不代表总体评分：

| 构造输入 | 辅助函数结果 | 这一结果说明什么 |
| --- | --- | --- |
| 写入后读取同一资源 | 1，确认一次 | 正常正对照可计分 |
| 无读取、读取失败、读取先于写入 | 各为0 | 时间与成功条件确实参与判断 |
| 要求写入但没有提交 | 0 | 空轨迹没有被算作完成 |
| 任务没有状态变化义务 | 不适用 | 不适用不能与零分合并 |
| 写入甲后成功读取乙 | 1，确认一次 | 此函数未约束同一对象 |
| 核验成功但状态变化字段为假 | 1 | 字段存在与字段为真不同 |
| 两次提交后一次无关读取 | 1，确认两次 | 同一读取可被两次提交复用 |
| 成功读取但没有上述标记 | 0 | 仅有成功事件还不够 |

十个场景包含三个需要收窄解释的确认路径和七个正常或否定对照。完整输入、结果与提取绑定保存在本次研究证据包；它们不是真实患者记录。

## 满分没有提供对象关联

研究解释是：时间关系可以支持“随后出现过读取”，却不能单独支持“这次读取确认了那次写入”。尤其是两次提交共用一次无关读取的场景，揭示的不只是对象身份缺口，还包括确认材料是否可复用的问题。这不意味着读取必须永远只能使用一次；它意味着逐效果确认的声明需要说明关联规则和复用语义。

状态变化字段为假的场景也不能简写成“系统把失败算成成功”。事件本身被构造成成功核验，函数检查的是字段是否非空。当前证据支持的判断仅是：字段存在性与状态变化真实性不能在解释分数时混为一谈。

这种区分对过程评估有实际价值。[论文第一版](https://arxiv.org/html/2610.15714v1)的作者报告，某一健康行政任务配置中，三次机会内通过率从0.267降至0.105，而子任务分从0.543升至0.633。这里引用的是作者结果，本轮没有重算；它只用于说明终局结果和过程指标应分开阅读，不能用本轮函数实验解释这些总体数值变化。

## 适配器可能已经承担了这项保证

最有力的反解释是：原始轨迹转成语义事件之前，适配器可能已确保对象一致性，或者其他维度会扣除无关读取的收益。若这一不变量确实存在，函数不重复检查可能是合理的职责分配。本轮没有执行从原始轨迹到适配器、再到总分的链路，因此没有排除这种解释。

原仓库设计还区分动作前、结果后和最终答复前的检查，并保留证据、义务与提交账本。这是公开设计材料，不是已经运行的端到端保证。[设计文档](https://github.com/Tomry1114/Awesome-Agent-Harness-for-Healthcare/blob/1b64350432708adfe26db60910db863ac782381d/HARNESS_DESIGN.md)

对过程评分的工程含义因此是一个责任问题：报告应写明对象关联由谁保证、哪些事件适用、无数据如何处理，以及确认材料能否被复用。若要宣称逐效果核验，就需要可审计的写入与读取关联。这个要求不等于本轮已经证明哪一层必须修改。

## 尚缺的端到端证据

下一项能够改变判断的证据，是原生有效轨迹确实产生了这种无关读取事件，并且能跟踪它经过其他维度和聚合过程后的结果。在此之前，不估计受影响样本比例，不推断模型排名变化，也不声称已经发现患者混淆事故。当前可以确定的边界只在这个函数：它检查后续合格事件，本身没有建立逐对象的效果关联。
