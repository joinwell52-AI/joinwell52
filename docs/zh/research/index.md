# 研究中心

研究中心不再把“研究节奏”和“研究领域”拆成两套并列目录。

正确结构是：**三个长期专栏，各自按时间持续积累文章；每日研究与每周综合是这些专栏的发布形态。**

## 三个长期专栏

### 1. 学术与论文观察

持续搜集、整理并讨论与 TMPA、Agent 治理、多 Agent 协作、工作流、评估和数字员工相关的论文。

- 按发布日期倒序归档；
- 每篇文章记录问题、方法、证据、局限和影响；
- 重要发现进入每周综合、架构修订或正式出版物。

[进入学术与论文观察 →](./papers/)

### 2. 行业与数字员工观察

持续跟踪企业数字劳动力、Agent Control Plane、岗位化 AI、治理和工作运行平台。

- 按日期形成独立观察文章；
- 区分厂商公开口径、可验证事实和本研究中心判断；
- 重点分析对 TMPA、数字员工架构和 CodeFlowMu 的影响。

[进入行业与数字员工观察 →](../industry/)

### 3. GitHub 与工程观察

持续跟踪开源 Agent、Runtime、Workflow、Skill、恢复、可观测性和多 Agent 工程项目。

- 按日期形成独立工程观察；
- 分析值得学习的机制与不应照搬的做法；
- 输出对 CodeFlowMu 的具体工程建议。

[进入 GitHub 与工程观察 →](../engineering/)

## 每日研究

每日研究不是一个杂乱汇总页，而是一篇自成体系的研究记录，通常包含三个栏目：

1. 学术与论文观察；
2. 行业与数字员工观察；
3. GitHub 与工程观察。

每个栏目都完成“搜集 → 整理 → 探讨 → 影响判断”。

[查看每日研究 →](./daily/)

## 每周综合

每周综合对三个专栏一周内的发现进行交叉分析，形成：

- 本周最重要的新证据；
- 对 TMPA 与数字员工架构的影响；
- 对 CodeFlowMu 的工程建议；
- 需要继续验证的问题。

[查看每周综合 →](./weekly/)

```text
三个长期专栏
    ↓ 每日独立观察
每日研究
    ↓ 跨来源综合
每周综合
    ↓ 稳定判断
架构、规范、工程任务与出版物
```
