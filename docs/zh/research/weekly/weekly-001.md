## 核心综合

首期周报建立了 Research Center 的研究基线：

1. 互操作正在成为基础设施，而治理仍是缺失上层；
2. 开源系统正从聊天 Agent 转向 Runtime、编排和操作者控制；
3. 企业厂商正在封装数字劳动力产品，而不是抽象 Agent 能力；
4. CodeFlowMu 不应成为另一个通用多 Agent 框架；
5. 稳定方向是面向中小企业的数字员工开发与运行平台。

```text
数字员工
= 岗位
+ 职责
+ Skill
+ Workflow
+ Runtime
+ 治理
+ 评估
```

## 学术信号

围绕 MCP、A2A、ACP 等协议的研究表明，工具访问和互操作并不会自动提供成员关系、责任、异议、人类升级、审计和回放。TMPA 因此应位于互操作协议之上或旁侧，成为工作数据与治理架构，而不是竞争另一个通用通信协议。

## 开源工程信号

OpenHands、AutoGen 等系统正增加可恢复执行、嵌套团队、Skill、Plugin、MCP 集成、连接健康和操作者控制。这些正在成为 Runtime 基础能力，但仍未定义持久组织岗位、责任所有者、完成证据和发布权威。

## 企业信号

- **ServiceNow** 把岗位化 AI Specialist 放入确定性工作流、升级和集中治理；
- **Workday** 把 Agent 当作具有所有权、成本、合规和生命周期的劳动力资源；
- **Salesforce** 按业务职能封装结果，而不是销售抽象多 Agent 能力。

市场信号很明确：组织购买的是完成的工作，而不是框架术语。

## 对 TMPA 的影响

TMPA 应保持协议无关，把治理定义为可执行生命周期控制，坚持 SME-first 定位，并评估证据、升级、恢复、人类介入和成本，而不是只看任务成功。

## 对 CodeFlowMu 的影响

建议正式定位为：

> **CodeFlowMu 是面向中小企业的数字员工开发与运行平台。**

初期重点是岗位定义、数字员工名册、Workflow 与 Operation Node 契约、Runtime 可观测与恢复、TMPA/FCoP 证据生命周期，以及成本与评估记录。

## 结论

CodeFlowMu 的价值不在 Agent 数量，而在于把概率型执行转化为可问责、可恢复、可度量成本和价值的组织工作。
