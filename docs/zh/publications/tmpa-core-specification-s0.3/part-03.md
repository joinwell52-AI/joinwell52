# 10. 一致性与可测试性

## 10.1 一致性层级

1. **TMPA Core Conformance：** 实现持久文本消息与状态对象、主载体规则、单写者流、异步多流推进、确定性聚合与重建、类型、角色、生命周期、完整性验证与恢复要求。
2. **FCoP Profile Conformance：** 通过已记录的 FCoP 投影满足 Core，并实现发布的命名、生命周期、原子迁移、路由与证据规则。
3. **Authenticated Governance Conformance：** 满足 Core，并通过可信签名、密钥与授权 Profile 验证创建者身份。

这些层级都不认证参与者声明的语义真实性。

## 10.2 C01–C14 必需测试

| ID | 测试 | 通过标准 |
|---|---|---|
| C01 | Schema 验证 | 缺少必填字段、类型错误、禁止顶层字段、不完整签名组或无效时间格式的对象退出权威集合并产生确定性问题 |
| C02 | 主载体与单写者不可变性 | 保持一个稳定任务载体；更正和取代通过新的可归属证据表示并保留原对象 |
| C03 | 重复对象 ID | 同 ID、不同规范内容的候选全部保留，均不得被选为权威节点，并产生确定性关键冲突 |
| C04 | 串行流连续性与异步推进 | 每个写者保持局部序号；重复与缺口被报告；无关流可独立推进；同集合的到达顺序不改变结果 |
| C05 | 角色权限 | 超出有效角色范围的动作保持可观察，但不应用于权威状态 |
| C06 | 生命周期合法性 | 未定义或未授权迁移保持为问题且不改变权威生命周期状态 |
| C07 | 职责分离 | 同一身份不得执行并独立复核同一结果，除非存在 Profile 授权的例外对象 |
| C08 | 完整性篡改 | 修改被覆盖内容同时保留原完整性元数据时，Digest 验证失败，相关对象退出完整权威集合 |
| C09 | 缺失引用 | 未解析的必需目标出现在问题集合中，依赖保持 `undetermined/partial`，不得视为已满足 |
| C10 | 禁止环 | 受影响子图被隔离和报告，未受影响对象继续可重建 |
| C11 | 聚合与重建确定性 | 同一最终候选集合和固定 Profile 的各种枚举与交付排列产生字节等价的规范偏序图与问题集合 |
| C12 | 冲突保留 | 互相矛盾的有效复核保持 `undetermined/disputed`，直至出现新的授权解决对象 |
| C13 | 恢复 | 全新 Reader 从持久证据重建责任、生命周期、未解决依赖和问题状态 |
| C14 | 终态历史保留 | 进入终态或归档后仍保留完整重建所需对象和迁移 |

测试是行为性的。实现可以采用不同存储、索引或执行机制，但可观察结果必须满足相同标准。

## 10.3 Fixture 与结果报告

一致性 Package 应发布有效和无效 Core 对象、FCoP TASK/REPORT/ISSUE/REVIEW、非法迁移、越权角色、职责分离、破损 Digest/签名、重复 ID/序号、序号缺口、缺失引用、禁止环、矛盾复核、受控中断恢复、终态保留，以及预期规范候选集合、治理图和问题集合。

每个结果应标识 TMPA Schema 版本、Profile 版本、Reader 版本、规范化 Profile、输入 ID 与 Digest、预期 valid/invalid/undetermined、视图分类、排列方法与数量、Runner 命令、执行日期和结果。

C11 仅在聚合器产生预期候选集合，且每一种同集合排列的规范治理图和问题集合均字节等价时通过。

## 10.4 合规映射

TMPA 提供技术控制，不自动形成法律认证。部署可以把 TMPA 字段和测试映射到组织问责、日志保留、人工监督、身份授权、职责分离、事件调查和证据完整性要求，但必须说明完全支持、部分支持、不支持或范围外，并指出依赖的外部身份、策略、保留和安全系统。

# 11. Profile、版本与出版规则

TMPA Core 定义可移植治理语义。Profile 可以增加文档类型、生命周期、存储映射、身份绑定、完整性策略或应用规则，但必须标识版本、声明 Core 一致性层级，且不得在继续声称相应一致性时削弱 Core MUST。

改变必填字段、权限语义、生命周期合法性、规范化、Reader 输出、问题分类或 C01–C14 通过标准的修改，需要新 Core 版本。Conformance Report 必须标识精确 Core/Profile/Reader/规范化版本、Fixture、来源修订与执行环境。

发布规范只建立 `specified` 证据层级；代码可建立被测试路径的 `implemented`；边界明确的运行可建立 `demonstrated`；没有外部实现、重跑或组织依赖，就不能声称 `independently adopted`。

## S0.3 理论对齐

文本协议可以由概率性 Agent 解释执行，而一致性和治理结论必须由确定性验证产生。因此，本规范把委托权限、生命周期验证和治理判断独立于模型解释进行定义。

治理判断采用三个语义值：

- `valid`：证据和适用治理规则建立接受；
- `invalid`：适用规则建立拒绝或违规；
- `undetermined`：证据不完整、冲突或等待解决，不允许二元结论。

实现必须保留 `undetermined`，不得在没有授权解决对象时把未解决证据转换为 `valid` 或 `invalid`。若一个对象依赖 `undetermined` 对象，其自身判断必须保持 `undetermined` 直至解决。

视图分类是派生展示而不是额外语义值：authoritative 对应 valid；quarantined 表示因确定违规而退出权威图；partial、disputed 和 pending_human 分别表示 undetermined 的不同原因。
