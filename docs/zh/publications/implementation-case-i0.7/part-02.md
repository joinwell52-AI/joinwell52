# 6. V1.4.0 → V1.4.1 修复分析

修复对照严格限定范围。V1.4.0 已经通过 C02 与 C07；当时失败的是 C06 与 C12。

## 6.1 C06——生命周期不等于验收

V1.4.0 在生命周期证据看似充分、但缺少独立验收时仍允许 `review → done`，从而把流程推进与业务验收混为一体。V1.4.1 分别计算两类判断：没有独立验收，工作保持 `review`，同时输出生命周期与验收不确定。产品不再从不完整权威链中制造“完成”。

## 6.2 C12——只有授权解决者可以清除冲突

V1.4.0 能保留矛盾复核，但允许后续未授权裁决清除争议。V1.4.1 保留未授权 DEV 裁决作为证据，产生权限问题，并让 `UNRESOLVED_CONFLICT` 继续有效。只有来自已分配、具有 `resolve_review_conflict` 权限的角色的裁决对象——本次以 PM 演示——才能解决冲突。

## 6.3 回归边界

C03 继续负责同 ID 异内容的候选冲突；C10 继续负责禁止引用环。两者都没有被并入 C12，且回归继续通过。若补丁通过弱化或重定义相邻准则来取得成功，就不能构成 S0.5 demonstrated 证据。

# 7. WP-13 多 Agent 证据门禁案例

WP-13 回答的问题不同于 C01–C14 Bundle：角色分离的工作流能否阻止未经核验的完成声明成为权威交付事实？

```text
带完成含义的声明
        ↓ 持久证据不完整
PM 事实核验 → 暂停 / 不发布 / 不派 QA
        ↓ 同任务恢复
DEV Commit + Report
        ↓ 独立角色
QA 复跑与报告
        ↓
授权 Gate C 裁决
```

最初 DEV 子执行使用了带完成含义的语言，但退出状态、测试、Commit 与正式报告并未全部建立。PM 检查持久事实，暂停发布且未派 QA。恢复后，DEV 补齐证据，角色分离的 QA 重新执行测试与检查。后续 Gate C 记录完成业务验收；Active、Push/发布和 Archive 仍是分开的裁决。

该案例演示证据门禁、职责分离、同任务恢复与分阶段权威。它**不证明**模型不再产生幻觉，不保证所有错误声明都会被发现，也不表示原始 V3 快照已经包含终态批准。其快照边界记录 `runtime_bound: false`，TASK-019/020 仍为 `review / pending`；后续验收不得倒写为早期快照事实。
