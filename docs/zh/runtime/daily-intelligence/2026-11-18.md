# 2026-11-18 Agent 核心研究与竞品动态

本轮核心判断：企业治理正在具体化为显式数据授权、按执行证据恢复、可重复评测和跨端审计。多Agent交付还需要区分子任务终态、结果消费和实际独立审阅。

### O1 ADK：MCP 参数不再自动读取会话状态

11月17日已提交，破坏性安全变更。MCP 服务原来可通过声明参数名读取同名 session 字符串；现在仅接收开发者显式提供的 arguments，默认不发送。旧 prompt 参数需要迁移。这里是代码确认的边界修正，不能称已确认生产泄漏。

[原始证据](https://github.com/google/adk-python/commit/889ddd3134df1dd1a626205ee78811950dec2a5c)

### O2 OpenHands：发送后504不应自动重跑

11月17日 #6547 已合入。发送后504返回 X-Should-Retry:false 和 conversation ID；明确发送前超时才允许重试。原运行可能继续，手动无键重发仍可能重复。上游仍注明缺少同一默认客户端流程在 base/head 的完整对照；未跑需密钥的真实模型配方。

## 研究分析

### A1 恢复研究应先判定是否已经执行

[O2](#o2) · [O3](#o3) · [O4](#o4) · [O5](#o5) · [O8](#o8) · [O9](#o9) · [O11](#o11)

已有证据：OpenHands避免发送后重试，Paperclip只在执行前证据充分时续跑，Orca把等待人和正在工作分开。待验证：CodeFlowMu重启后的任务是否保留这种区分。实验候选：分别注入发送前/后超时、满盘和审批等待重启，统计重复动作、人工等待、恢复时延；不预报通过。FCoP比较状态/回执/证据，重试预算、租约和磁盘预留归Runtime。代价是故障注入与未知状态处理。互动：结果未知时，哪些证据足以安全接替？

### A2 企业治理向身份、审计和可执行评测延伸

[O1](#o1) · [O15](#o15) · [O21](#o21) · [O23](#o23) · [O24](#o24) · [O25](#o25) · [O27](#o27) · [O28](#o28) · [O34](#o34)

### A3 委派结果、根任务状态和独立审阅需要不同证据
