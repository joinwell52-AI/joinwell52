# 2026-11-11 · Agent 核心研究与竞品动态

本轮最重要的结论：企业 Agent 治理正在落实到调用身份、审批归属、回执与失败语义；而真实部署与测试通过之间仍有明显鸿沟。Paperclip 的预发布事故是反例，Orca 的跨主机编排也仍有未启用部分。以下 26 项事实观察支撑 6 组分析，分析不另算新增事件。

## 研究分析

### A1 · O3 / O4 / O5 / O6 / O15 / O18 / O26

授权要随执行对象和代际重核，代办权限不必等于接触秘密。证据支持调用前重核、审批归属、秘密单次揭示的不同机制；待验证的是把它们接到 CodeFlowMu 岗位委派与凭据代理后，是否能覆盖跨员工/组织切换。主要落在 Runtime/适配与产品治理层，不直接新增 FCoP 内核规则。实验候选：审批后换身份、移除原 Agent、并发 reveal。互动议题：授权版本变化后，已批准但未执行的动作如何失效？

### A2 · O1 / O2 / O8 / O9 / O14 / O17 / O22

协作交付需要区分投递、接受、执行、结果与恢复证据。中断记录不证明副作用未发生；事务回执只在其保护的资源上提供较强恢复依据。待验证：FCoP 工件中的任务/事件/结果语义，能否与 Runtime 的调用身份、回执及 unknown outcome 正确对应；不要把持久化、调度和所有权实现全推给协议。实验候选：执行后掉回执、消息接受后不再推理、损坏事件文件与断连纠偏。

### A3 · O7 / O10 / O11 / O13 / O18 / O20 / O22

治理必须看真实边界与失败行为。默认继承环境、advisory 冲突标签、readOnly 声明与真正拦截不是同一级保证。已支持的判断是：失败应保留原错、阻断不安全派发且不虚报成功。体验候选：bulbasaur 技能包锁定和冲突检查；先核验安装方式、许可与维护成本，当前未安装。互动议题：运行时重新读取策略失败时如何保持拒绝语义？

### A4 · O12 / O13 / O17 / O21 / O23 / O25

互操作应按层比较：MCP Apps/WebMCP 是视图工具面，ACP 是客户端与 Agent 会话配置，A2A 是跨 Agent 接口；Orca 的跨机协调仍有 inert 段。FCoP 的文件/工件协调可与这些互补，现有证据不证明是同层替代。体验候选：ACP registry 应用与 AG2/MCP Apps；代价包括 Node/登录、协议版本、host 支持、沙箱服务与成本。DSPy 3.5 则先做独立迁移评测，不直接当数字员工成品。

### A5 · O16 / O22 / O23 / O25

独立验收要查留下的状态，并让故障模型接近真实部署。Paperclip 的预发布反例与 LangChain 的结果验收建议相互呼应；它们支持研究方法，不能推出所有项目都已解决可靠性。实验候选：同机重启对比跨进程空间 redeploy，以任务完成、审计和副作用判定，另外保留没用于调参的案例。互动议题：K15 之后是否仍有不同 hostHash 无法判定前主死亡的阻塞类？

### A6 · O14 / O15 / O16 / O17 / O18 / O19 / O20 / O21 / O24

竞品重估：Paperclip 的受治理业务动作与恢复证据学习价值高、竞争风险高，但预发布事故使可靠性判断保持审慎；Orca 的多端协作与外部聊天 API 风险中高，跨主机编排尚未完整启用；Orkas 与 Agentlas 的兼容探测/升级价值中高、交付竞争风险中；Vibe Kanban 保留低频观察并核查 sunset 判断，不能据提交认定商业复活。未发现足以改变本轮商业 License 判断的已核验证据。
