## 研究分析

### A1 · 优先实验：交接时沿用哪版任务、规程与授权？

依据：O4、O5、O6、O25、O35、O36。

已有证据：上游分别把父任务证据、持久化 cutoff、当前问题 ID 和受理时 quiet_rule 纳入判定，StaffDeck 将 SOP 需求与权限分开。昨天独立实验已在 CodeFlowMu 产品接口/FCoP 4.0.5 上验证受控换版路径：12次执行、24次复核判定（12份正式复核）和1次缺原文测试；两张单续验只对获批工单换到 V2，银行核验均复用0次重跑，减免执行/复核仅获批单各重做1次。待验证：这些是合成数据和程序解释规则，没有大模型自主判断。最高价值下一实验是让真实执行/复核 Agent 在 V1→V2、待批→生效、撤权、原文缺失、跨班身份变化中各自取证，观察是否错误沿用最新版或旧批准。适用前提是能取回指定原文和针对本单本轮的决定；代价是版本存储、决定有效范围和独立复核成本。FCoP 可研究文件引用/版本/决定/证据的可追溯契约；授权执行和缓存失效属于 Runtime/适配层。归类：实验候选（高优先）；今天未执行，不派工。互动议题：证据已变化时，恢复审批的旧结论如何失效？

### A2 · 优先实验：结果未知时恢复交付，还是再次执行？

依据：O8、O14、O18、O20、O29、O31、O34。

已有证据：MCP 404 不重放在途调用，A2A send once 明确未知结果，Orca 无回答重试受副作用证据约束；Paperclip 显示接受结果后的漏投与跨 blocked cycle 重唤醒是两类问题。待验证推断：稳定 ID、退避、回执和工件检索需要组合，单个幂等 key 或“运行成功”不足以证明员工完成交付。实验候选：用可计数外部账本，在动作完成后丢响应、报告保存前后崩溃、同/新任务轮次恢复、依赖确定性失败情况下，对比执行次数、已接受结果、报告投递次数和人工验收；加入实际撤权再恢复。FCoP 研究任务轮次/报告/回执/结果未知的语义映射，重试次数与退避放 Runtime；不先把上游机制推为内核改动。代价是独立外部真值和故障注入；承接旧19A4/17A2等，不冒充已验证。互动：丢回执但动作已发生时，允许怎样查询而不重发？

### A3 · 重点研究：岗位身份、账号凭证和委派额度分别约束

依据：O3、O12、O13、O15、O16、O30、O37、O43。

已有证据：会话 owner、可用账号、专员路由与原生 child grant 是不同层；社区 #6215 提供“交接不改变 bearer”的具体实验主张，但仍 OPEN。Paperclip 账号限额等待说明账号变化会影响活性，不自动证明新账号获同一任务授权。待验证推断：企业数字员工应分别回答谁发起、谁执行、代表谁、可以委派给谁；给 _meta 写名字不等于可验证身份。候选实验比较共享 token、逐专员 token、token exchange 与撤销，跨两个租户/账号和同名专员；共享预算测试并发预留、失败计数、恢复后额度，#6211/#6212 只作开放设计参考。适用需身份源/工具服务协作，增加 token 服务与审计成本。FCoP 可比较委派/责任证据字段，凭证签发、调用前鉴权和限流属 Runtime/网关。归类：实验候选与持续观察；互动：工具服务能验证的 acting-agent 与 represented-user 如何区分？

### A4 · 重点实验：长任务活性、Stop 与证据投递分别验收

依据：O19、O21、O22、O23、O35、O38、O44。

已有证据：等待子任务可能被误判 idle、状态锁等待可能耗尽工具线程、慢 webhook 可能把完成拖成 busy，Windows 共享 server 可能无法证明某聊天进程已停止。它们都不能靠 /alive 或一个绿色状态解决。候选为真实父子长任务＋高频订阅＋慢 webhook＋断线 Stop 的交叉故障实验；分别看任务是否前进、动作是否确实停止、历史能否读取和晚到事件是否归属正确。线程/进程隔离提高资源成本，持续 heartbeat 不能替代原子 pause 或遗留子进程回收。FCoP 只研究可观察状态/证据关系，进程组、线程池、租约与 idle 策略属于 Runtime。归类：实验候选；互动：父任务取消后仍运行的 child 如何从活性证明过渡到可核验回收？

### A5 · 协议与开源体验：按层组合，先测一条完整岗位流程

依据：O1、O14、O24、O25、O27、O39、O40、O41、O42。

已有证据：Claude 的 Skills/Tasks/Elicitation 是工具服务端工作流交付，A2AClient 是远程消息/任务接入，FCoP 是本项目文件/工件协作契约；OpenHands 项目/board 与 StaffDeck 员工/SOP 是应用/运行层，不应统称同层协议竞品。体验候选优先 StaffDeck #325 与 OpenHands 两个正式版本，固定版本核对 License、安装/迁移/恢复路径，完成“接工单→请求人工输入→子任务→报告→复核”一条流程；手机看审批/证据/暂停而非屏幕缩小。Orca 分享仍仅契约，Paperclip swarm 有不可观测/自动批准 helpers 边界，不能因功能表相似推成熟。代价是环境、账号、商业条款与维护接入成本；MIT 源码不推及托管服务条款。全部未安装实测。MCP Events/Skills 的早期协议状态是历史背景，不把生日回顾当新协议发布。归类：体验候选、协议持续观察。

### A6 · 治理研究：删除、脱敏、签名和审计不能互相替代

依据：O2、O9、O11、O17、O26、O41、O42、O45。

已有证据：SDK 结果编辑有明确 publication 边界和对象绑定；ADK/Gemini 的凭证信息曾从另一观测入口绕出；Paperclip 删除扩展至 handoff/训练快照等副本，签名仅验证来源/完整性。待验证推断：数字员工的资料跨工具、记忆、报告、审计和训练导出传播，应建立可追溯副本清单，并比较撤权删除与必要审计证据如何兼容。实验候选用合成敏感标记，覆盖 raw/structured/meta、Trace、session replay、升级恢复及导出；外部系统真实内容不用于探针。FCoP 研究工件来源/派生关系与允许留存的证据摘要，Runtime/连接器执行脱敏/删除；保留 hash 不证明原文可取回、无敏感泄漏或法律合规。代价是存储血缘与扫描成本，范围限定、负例优先。归类：实验候选；互动：删除结果正文后，哪些最小事实仍足以证明曾获授权且执行过？
