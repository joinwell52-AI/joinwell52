## 第二层：研究分析

### A1. 企业治理的授权单位，需要细到主体、资源、动作与当前问题

**依据：O2、O6、O10、O18、O21、O24**

已有证据：过期 interrupt、MCP owner 环境、被撤销凭据、会话授权误持久化和显式实体映射，都说明一次登录或一份角色说明不能独自表达执行权。待验证推断：CodeFlowMu 可研究把岗位/委派依据、人工决定版本、当前执行主体和资源范围关联检查；目前未证明本地存在对应缺陷。实验候选 E1：同一任务经转派、撤权、第二次审批和工具环境切换后，重放旧答复/旧凭据，观察实际动作是否仍被接受。交互议题：LangGraph 的旧 ID 兼容回退与应用层 approval revision 如何共同约束？

### A2. 协作协议研究应比较消息语义与证据契约，并区分 Runtime

**依据：O1、O5、O7、O8、O12、O15、O17、O27**

已有证据：AG2 区分观察与执行，Codex 区分记录与模型采样，A2A 区分私有持久状态与公开 Task 投影，MCP Apps 以安全属性约束宿主而不固定 iframe 结构。待验证推断：与 FCoP 比较时，应问任务/工件/事件 ID、状态变更、交付确认、证据引用和互操作如何表达；Runner park/claim、工作区复用和进程回收属于 CodeFlowMu Runtime/适配层。不能仅因都用文件或消息，就说是同层替代。资料候选 C1 的 MCP 异步审批/Events 值得补查，但实质提交早于窗口，不计新增。

### A3. 持续履职需要“可继续”与“可完成”的不同证据

**依据：O3、O13、O14、O19、O20、O29、O30、O31**

已有证据：Paperclip 的交付物复核、文件恢复 hold、OpenAI 的 unknown effect、Orca 的 worker 活性及不同 CLI 的 cancel 范围，分别处理不同生命周期事实。重试成功、会话还活着、文件已救回，都不能自动证明任务已完成或可以重放副作用。待验证推断：数字员工产品可把待输入、后台仍工作、结果未知、恢复阻断、待独立验收分别呈现。E2 候选：在副作用后/回执前、交付后/状态提交前、转派后/旧 run 结束前中断；核对外部效果、凭据和当前负责人。互动议题：Paperclip #19186 与 #19130 的所有权/发布检查如何在同一提交边界组合？

### A4. 数字员工的记忆应有来源、修订和写入职责

**依据：O1、O6、O9、O22、O23、O26**

已有证据：Anthropic 用业务只读/蒸馏写入分工和文件索引保留经验，仍承认夜间污染与未完成会话遗漏；AG2 共享作用域和 ADK 并发修复说明共享记忆不等于无冲突；Codex 记忆整理只授予专用写根。待验证推断：岗位经验、任务状态、个人偏好和组织规则可分别研究生命周期，不将它们混成一个可任意更新的库。E3 候选：合成过期 SOP、恶意工具输出、跨用户样本及中断会话，检查事实替代、来源保留、审核前生效和回滚。此处是实验设计，尚未运行。
