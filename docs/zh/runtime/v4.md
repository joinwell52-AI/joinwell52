# Research Runtime Center V4

## 一句话定义

Research Runtime Center V4 是数字研究员的运营中心：三个栏目分别选题，上午推进研究，下午生产完整报告，晚上完成 GitHub 与网站发版。

## 三个栏目

每日 10:00 的 Research Runtime Queue 必须分别对以下栏目作出决定：

1. **数字员工**：岗位、职责、工作流、运行、治理与评估；
2. **行业架构**：企业 AI 运行模式、控制平面、工作系统与组织架构；
3. **开源工程**：开源运行时、协议、工具、基准、恢复与可观测性工程。

每个栏目必须显示：

- 今日选题，或“未选题”；
- 选题原因或未选题原因；
- 主要来源；
- 优先级与生命周期；
- 下一步。

## 每日班次

| 时间 | 班次 | 工作成果 |
|---|---|---|
| 09:00 | Research Runtime Engine | 严格推进一个受治理生命周期转换。 |
| 10:00 | Research Runtime Queue | 来源发现、候选评分、三栏选题计划。 |
| 11:00 | Research Runtime Knowledge | 合格研究笔记的知识准入与架构候选。 |
| 15:00 | **Research Runtime Production** | 完成中英文报告、配图、引用与出版编辑，形成 Publication Candidate。 |
| 20:00 | Research Runtime Publication | 发布完整候选、更新索引和网站、提交并验证 GitHub。 |

周一 12:00 另有架构评审；周日 20:30 生成每周综合；周三 10:00 运行学术研究。

## 15:00 生产班次

下午班次执行已有 Research Skills：

```text
Skill 05 — Research Writing
→ Skill 06 — Visualization
→ Skill 07 — Evidence & Citation
→ Skill 08 — Publication Editing
```

输出不是半成品草稿，而是完整的 **Publication Candidate（出版候选）**：

- 中文 Markdown 完整；
- 英文 Markdown 完整；
- 元数据与栏目归属正确；
- 配图完成，或明确说明不需要配图；
- 证据与引用完成校验；
- 出版编辑完成；
- 尚未进入公共文章目录。

## 20:00 发版班次

20:00 只负责发布，不重新研究或写作：

```text
Publication Candidate
→ 中英文公共文章
→ Metadata / Index / Website
→ GitHub Commit
→ Commit Verify
→ Release
```

候选未通过发版门禁时，应退回 Production 或更早的研究阶段。

## 三类权威运行产物

```text
research/runtime/YYYY/MM/YYYY-MM-DD-runtime.md
```

记录每个班次的状态、输入、工作成果、输出、下一步和 GitHub 证据。

```text
research/runtime/plans/YYYY/MM/YYYY-MM-DD-plan.json
```

记录三个栏目的每日选题决定。

```text
research/runtime/candidates/YYYY/MM/YYYY-MM-DD-candidates.json
```

记录 15:00 形成的完整出版候选，供 20:00 发版使用。

## 完成率

只有 `Completed` 计入完成率：

```text
完成率 = 已完成任务数 ÷ 当日计划任务数
```

`Waiting`、`Running` 尚未完成；`Skipped`、`Blocked`、`Failed` 虽已终止，也不算完成。

## 最高原则

> 每个定时任务都必须汇报实际工作成果，而不是只汇报“执行完成”。

> 下午生产完整报告，晚上只负责正式发版。

> 没有 Runtime Record 和 Commit Verify 的发布，不属于正式运行结果。
