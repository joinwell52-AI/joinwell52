# Research Runtime Center V5.0

**状态：** 架构冻结  
**调度器：** Research Runtime Scheduler V3.0  
**生效日期：** 2026-08-05  
**时区：** Asia/Shanghai

## 为什么必须升级到 V5

V4 把长期 Research Program 与 Daily 生产线混在一起。09:00 Engine 先推进长期对象，而当天新选题到 10:00 才产生，导致新对象无法在 15:00 Production 之前完成 Reading 与 Analysis。

V5 彻底消除这个结构冲突。

## 四套独立 Runtime

| Runtime | 职责 | 输入 | 输出 |
|---|---|---|---|
| Daily | 当天发现、研究、生产、发布 | 当天信号 | Released Daily Research |
| Weekly | 可独立阅读的 AI Research Brief | 过去七天已验证 Daily Research | 重要变化、相互联系、证据与争议、可支持的判断、开放问题 |
| Academic | 正式学术观察 | Paper、Benchmark、Specification、Institution | Academic Observation |
| Program | 长期受治理研究 | 独立 Program Queue | Program 状态转换与 Program Publication |

四套体系分别维护 Record、Queue 与运行时间线。

## Daily Runtime

```text
09:00 Discovery → Signal Pool
10:00 Queue → Today's Research Plan
11:00 Reading → Reading Result
13:00 Analysis → Research Object
15:00 Production → Publication Candidate
20:00 Publication → GitHub + Website + Commit Verify + Release
```

Daily 的三个栏目是 Digital Employee、Industry Architecture、Open-source Engineering。每天每个栏目必须明确为 `Selected` 或 `No Selection`。

## 阶段权威

- Discovery 执行三条 Research Intelligence Profile；
- Queue 只执行三栏选题；
- Reading 执行 Skill 03；
- Analysis 执行 Skill 04；
- Production 执行 Skill 05–08；
- Publication 只负责发版。

自 2026-08-12 起，Analysis 与 Production 同时执行 Editorial Architecture V2：研究问题驱动、可扩展文章类型、动态正文模块、证据身份、研究独立性、六项编辑 Gate，以及可选且独立改写的 Community Edition。V5 Runtime 拓扑与阶段顺序保持不变。

Production 唯一合法输入是 `Research Object`；Publication 唯一合法输入是完整 `Publication Candidate`。

## 独立调度

- Weekly Runtime：周日 20:30；
- Academic Runtime：周三 16:00；
- Research Program Runtime：周一 12:00。

Program 覆盖 TMPA、FCoP、CodeFlowMu、Digital Employee、Research Operating System，永远不进入 Daily Runtime。

## Runtime Record

V5 分别在以下目录创建 JSON Record：

- `research/runtime/records/daily/`
- `research/runtime/records/weekly/`
- `research/runtime/records/academic/`
- `research/runtime/records/program/`

所有终态班次必须汇报 Input、Work Result、Output、Next、Metrics、Evidence、Artifacts。

## GitHub Actions 与 ChatGPT Worker

GitHub Actions 只负责打开执行槽；ChatGPT Worker 执行真实研究。执行槽在 Worker 写入合法结果之前保持 `Waiting`。Scheduler 禁止制造 `Completed`。

## 冻结规则

V5.0 完成后，四套 Runtime 的边界、Daily 六阶段和 Scheduler V3 的九个任务身份冻结。后续工作只做优化：来源质量、Worker 效率、指标、页面体验、证据质量与出版质量。
