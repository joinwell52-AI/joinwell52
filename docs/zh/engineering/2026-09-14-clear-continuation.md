# 清空了记录，为什么还会引用旧会话？

用户清空会话，再读历史列表，结果确实是空的。可是下一次整理上下文时，程序仍可能把旧响应编号交给模型服务。

删除记录与停止引用记录，原来是两件事。更棘手的情况是：数据库已经完成删除，但提交确认途中发生取消或错误。调用者看到失败，底层数据却已经改变；恢复逻辑该保留旧关系，还是让它失效？

我们围绕 OpenAI Agents SDK 的一个候选修复做了五项本地对照。完整候选代码全部通过；保持其他代码与测试不变，只换回旧清空方法，有四项失败，既有并发等待对照仍通过。问题因此收窄到具体引用的失效，而不是笼统地归咎于“没有并发保护”。

## 历史列表之外，还保存着什么

Agents SDK 的会话包装器可以把历史记录交给 OpenAI Responses 的压缩接口，生成后续执行所需的较短上下文。它既可以传入当前内容，也可以通过旧响应编号续接已有链条。

[PR #5000](https://github.com/openai/openai-agents-python/pull/5000)修复的正是清空后的引用残留。原方法已清除待延迟压缩的指针，并递增内部变更代次；但当前响应编号与最近未存储响应编号仍然保留。即使历史为空，后续调用仍能沿这些引用重新指向旧链条。

这项 PR 在本轮读取时尚未合入。我们固定其源码提交，而不是把候选修复写成已发布版本的普遍保证。

## 把删除与确认之间的间隙测出来

实验使用 Python 3.12.10、固定完整 SDK 源码与上游原测试。压缩接口采用 `AsyncMock`，因此我们能检查准备传入的参数，但没有访问真实 OpenAI 服务。四项是新增清空场景，一项是既有的并发控制场景。

| 受测场景 | 旧清空方法对照 | 候选修复 |
| --- | --- | --- |
| 正常清空后，不得继续使用旧响应编号 | 失败 | 通过 |
| SQLite 删除提交后，调用被取消 | 失败 | 通过 |
| SQLite 删除提交后，确认抛错 | 失败 | 通过 |
| 自动压缩模式在清空后改用当前输入 | 失败 | 通过 |
| 清空等待正在进行的压缩，最后保持空历史 | 通过 | 通过 |

第二、三行并非只把一个变量改成“已删除”。测试使用真实临时 SQLite 数据库，在 `commit()` 完成后暂停返回，再注入取消或确认错误。随后检查历史已空、锁已释放、旧响应链不可再用于压缩；候选修复还通过了后续写入和使用新响应编号的检查。

旧方法对照失败在“应该拒绝缺少新响应编号的压缩，却没有拒绝”等断言上。它证明本地包装器仍会走向旧引用路径，不能被解释成我们已经观察到远端服务器恢复了被删除的数据。

## 已有代次，也要清掉具体指针

容易想到的解决办法是增加一个“重置代次”。但这里已经有内部变更代次与修改锁。第五行对照也说明，即使换回旧清空方法，那项既有并发等待语义依然成立。

这次修复没有新增一套代次系统，而是在成功和异常清理分支中，补充清除两类遗漏的响应指针。代次负责识别状态是否发生变化；指针负责决定后续请求连接到哪里。前者存在，不能自动证明后者已经失效。

这一点会直接影响我们自己的工程评审：先列出现有续接引用，逐个核对清空的成功、取消和确认失败路径，而不是先设计一个新的摘要字段。测试也应检查下一次消费者真正读取的引用，而不只检查当前界面显示了多少条记录。

## 恢复任务时，还有另一种旧关系

同一轮 [Paperclip #13345](https://github.com/paperclipai/paperclip/pull/13345)处理的是另一层错位：供应商会话恢复到了正确位置，但调用提示没有带入用户修改后的任务说明，旧评论反而再次成为工作目标。

我们对其原说明选择函数另做了七组双版本检查。在已规范化唤醒对象的前提下，两组普通恢复输入由“只选简短任务标识”变为“包含当前完整说明”；新任务、重新分配和恢复动作等对照保持相应行为。这只是选择函数及辅助函数的实验，没有运行数据库中的目标选择流程，也没有重演真实供应商恢复。

两个问题不应被强行合并。SDK 清空需要切断已经失效的续接关系；Paperclip 恢复需要把当前任务说明送到仍在继续的会话。共同的检查方法是看下一次调用实际采用了什么，而不是仅凭“历史已空”或“会话已找到”作判断。

## 下一轮值得继续验证的边界

后续可以在我们自己的工程入口中做一张引用清单：历史记录、当前响应编号、延迟工作、待重试请求分别由谁读取，以及清空时由谁失效。对每个现有引用检验成功、取消、确认失败三条路径，再判断已有代次是否足够。

本轮没有证明跨进程重启、远端数据删除或通用权限撤销，也没有发现 SDK 需要新加代次机制。它提供了更小、更可操作的验收问题：**清空之后，下一个消费者还能不能拿到旧关系？**
