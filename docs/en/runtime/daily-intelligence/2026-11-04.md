### A1. Enterprise authority must bind the actual principal, turn and current permissions

**Evidence：O2、O4、O15、O20**

Supported: projects repair mismatches involving cached permissions, shared endpoints, cross-person turns and restored policy. Useful mechanisms name actor/onBehalfOf and revalidate authority at read, execution and restore boundaries.

Pending: CodeFlowMu role identity/delegation may need cross-checks with FCoP artifact authors; local implementation has not been examined, so no corresponding local defect is claimed.

### A2. Collaboration needs task semantics and durable messages without observation becoming execution

**Evidence：O1、O2、O3、O6、O12、O17**

Supported: AG2, ADK and Orca address task trees, branches, active-turn messages and delivery ownership. Issue artifacts and SDK sessions offer different carriers whose identity/state/recovery contracts can be compared; they are not all same-layer protocols.

Pending: FCoP files/paths/events can supply traceable collaboration contracts while runtime owns scheduling/execution. Adding ownership or scheduling to the protocol core requires separate evidence.

Track O2's worker stack, experience AG2 task semantics and use E1 for sibling progress/cancellation/handoff. Discussion: can observation, accounting and replies share identity without sharing execution authority?

### A3. Acceptance needs independent execution evidence beyond model text or mutable grading output

**Evidence：O2、O5、O7、O11、O24、O26**

Supported: SDK proposals separate artifact acceptance from publication; Claude fixes false success and audit reads have explicit failure semantics. OPEN SWE-bench/Orkas reports identify grading/narrative risks for verification, not universally confirmed failures.

Pending: REPORT should link tool results, actual authorization and independent REVIEW evidence rather than rely solely on worker narration. This is a design-research judgment, not a completed FCoP conformance experiment.

Experiment candidate E3: inject approval/completion claims and trailing PASSED text; check real approval and independent acceptance. Discussion: which operations block or degrade when auditing fails, and how are gaps preserved?

### A4. Recovery must preserve data, ownership and uncertain effects together

**Evidence：O2、O7、O8、O9、O13、O16、O19**

Supported: durable sessions, encrypted backups, message repair, paused archive restoration and uncertain-call reconciliation solve separate pieces. Strict Paperclip failures, symlink fallback and short-read limits show reopening alone does not establish continuity.

Pending: employee handover should reconcile the last verified artifact, active work, outstanding obligations and occurred effects. Required evidence differs by system; no general exactly-once claim follows.

Experiment candidate E2: interrupt after an effect but before persistence; compare duplicates, missing records and manual reconciliation. Discussion: independently prove backup, process termination and business acceptance.

### A5. Digital-employee governance also includes memory, SOPs and business semantics

**Evidence：O10、O18、O25、O27**

Supported: machine-shared memory, SOP publication/restart routing, supplied classifiers and approved business terminology affect what roles remember, how they work and how they interpret tasks. Snowflake features have mixed availability; StaffDeck reports remain unreproduced.

Pending: enterprise knowledge/SOP/memory needs evidenced versions, owners, role scope and effective state. Account sharing requires an explicit product contract; having memory alone is not maturity.

Experience candidates: Agentlas default memory and AG2 contexts in isolated profiles; research SOP publication/restart/routing consistency. Discussion: distinguish machine/runtime/role/account ownership of memory.

### A6. Assess frontier mechanisms together with delivery and migration costs

**Evidence：O1、O5、O12、O14、O16、O20、O21、O22、O23、O28、C1**

Windows bytes, first-use extension trust, hook mapping and removed APIs affect adoption costs. MACP offers cross-domain identity/capability architecture as a historical comparison candidate.

Pending: FCoP may combine with remote discovery/authentication protocols and harnesses, but fields/state/failure semantics require comparison. An Internet-Draft is not an adopted standard and a public repository is not production qualification.

Prioritize OpenAI SDK preview, AG2 and Orca as experience candidates; compare C1 semantics without changing Registry. Discussion: what conformance/delivery evidence supports protocol, adapter, runtime and product guarantees?
