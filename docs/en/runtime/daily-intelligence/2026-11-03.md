## 4. LangGraph Python SDK: clean stream closure is not run completion

**Status：#9554 MERGED; release inclusion NOT VERIFIED**

After a clean close without end/error, the SDK checks run status when Location names a thread-scoped run stream. Pending/running or transient check failures use the existing reconnect budget, backoff and cursor. Terminal status and cases such as non-429 4xx keep the ending behavior. Thread streams, missing Location and legacy threadless Locations are unchanged. The cost is an extra GET that may download a large run input again.

This prevents proxy timeouts or restarts from silently truncating answers as success. Pending CodeFlowMu/FCoP validation: separate connection termination from task completion and account for reconnect cost.

Worth discussing: can a lightweight terminal-state endpoint avoid fetching input again while preserving cursor idempotence?

**Primary public sources：** [#9554](https://github.com/langchain-ai/langgraph/pull/9554)

## 5. OpenHands SDK: encryption at rest for bash event logs

**Status：#6343 MERGED; general stable rollout NOT VERIFIED**

The public PR describes a disclosure involving bash logs exposed with a sandbox file tree; command/output logs can contain credentials. With a configured cipher, BashEventService writes Fernet tokens and reads with previous keys. Undecryptable files are logged and skipped. Legacy plaintext remains readable without automatic re-encryption, and no secret key still means plaintext writes. Deployment fixes moving state off published trees and uploading secrets belong to other repositories; this does not prove every deployment safe. A real sandbox was not tested in the PR.

The boundary includes logs, volumes and recovery archives. Pending CodeFlowMu/FCoP validation: protection with/without keys, rotation and legacy backups.

Worth discussing: legacy plaintext migration/deletion and whether unreadable events become explicit audit gaps.

**Primary public sources：** [#6343](https://github.com/OpenHands/software-agent-sdk/pull/6343)
