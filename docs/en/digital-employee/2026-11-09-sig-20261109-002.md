# When a repair proposal becomes a host action: eight probes of a response boundary

A text interceptor can record an intervention as enacted while the response returned to its caller remains unchanged. The records answer different questions: one concerns the repair layer's decision; the other concerns whether the host response applied it. For engineers maintaining agent adapters, the useful question is which boundary preserves which properties, and which protections still depend on another layer.

This article uses the completed same-day Research Object to examine eight isolated probes of a pinned ARIA response adapter. The bounded result is that plain-text substitution preserves the tested metadata, tool-only responses return unchanged, mixed responses delegate protection, and failed application to an immutable response corrects the audit to unenacted. These observations do not establish full-system safety or rollback of an external write.

## Recovery can change different objects

UiPath Maestro's process-instance documentation distinguishes pause, retry and Go to. Pause waits for running steps to finish; retry continues current activities from the last completed step; relocation requires a subsequent Retry or Migrate and may require manual variable repair. Its case-instance page describes different semantics: pause freezes SLA timers and new task activation while existing running tasks retain their state; retry targets failed tasks or transitions, and migration preserves stage, data and audit history. [Process-instance documentation](https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/process-overview-homepage), [case-instance documentation](https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/how-to-manage-live-case-instances-pause-migrate-and-retry).

LangGraph's interrupt documentation says that resumption restarts an interrupted node, including code before the interruption; a parent invoking an interrupted subgraph also restarts. Its fault-tolerance documentation distinguishes graph state from external writes, explains node retries, and treats a lost provider acknowledgement as an unknown outcome requiring provider-side reconciliation. [Interrupt semantics](https://docs.langchain.com/oss/python/langgraph/interrupts.md), [fault-tolerance semantics](https://docs.langchain.com/oss/python/langgraph/fault-tolerance.md).

These are official source statements; we did not run those products. Process position, replayed nodes and pending response text are different units of change. They cannot be combined into one transaction-rollback guarantee. The measurement here concerns the third unit: adapting text before a host response is delivered.

## What the eight probes actually exercised

The internal experiment extracted the response adapter and helpers from revision `ce68c040cca0796b37fa8ae46e2a87a073f64001` and called them with synthetic response objects. The text interceptor was a deliberately non-validating test double: it requested replacement text and recorded protection flags. The actual lower validator, learned controller, model and native framework were not executed. This design separates rejection performed by the adapter itself from rejection delegated elsewhere; it is not a complete protection test. [Pinned implementation](https://github.com/LabRAI/ARIA/blob/ce68c040cca0796b37fa8ae46e2a87a073f64001/src/inference/native/model_hooks.py), [probe record](/assets/evidence/2026-11-09-sig-20261109-002/adapter-probe.json).

| Input or condition | Internal observation | Supported boundary claim |
| --- | --- | --- |
| Plain text | First-choice text changed; identifier, usage, finish reason and second choice remained; original input was unchanged | Copy-and-substitute preserved these fields in the tested object |
| Tool-only and legacy function-call responses | Original object returned; protection flag and pending tools forwarded | This path does not insert the test double's replacement into the host |
| Text plus tools | Protection flag forwarded; the non-validating double still caused text replacement while tool fields remained | Protection depends on a lower layer; this does not establish a real-controller vulnerability |
| Structured nontext content | Original object returned without calling the text interceptor | This content type bypasses text substitution |
| Intervention disabled | Object unchanged; interceptor not called | Negative control behaved as expected |
| Immutable host, fail open | Original response returned; audit corrected to unenacted | A successful request can be separated from successful host application |
| Immutable host, fail closed | Exception raised; audit also corrected to unenacted | Failure policy changes the caller outcome without recording failed delivery as enacted |

The two tool-only representations are separate cases, making eight in total. These are internal source-derived isolated observations, not an independent reproduction. An initial harness run failed on default character decoding; explicit encoding corrected the environment issue. That correction was not a product fix.

## Why an enactment flag still needs host-delivery evidence

The interesting result is the difference between records at different layers. In the tool-only fixture, the double's audit still contains an enacted flag and replacement content, yet the adapter returns the original object and adds host-unchanged boundary information. For the immutable host, an application exception instead clears enactment and restores the original delivered content. Reading only one lower-layer flag can conflate proposal, application and final return.

Our interpretation is that audit fields must be read with the layer they describe. Acceptance of a proposal does not substitute for evidence that the host object changed. Successful host delivery does not substitute for confirmation that an external provider completed an action. We did not test a complete acknowledgement-binding design or establish correct audit correction for every real response type.

ARIA's repair-rerun implementation separately checks native termination and resolved evaluation, retains variant artifacts and rejects unresolved evaluations. It illustrates a related boundary: a run ending does not establish task success. This is a static observation of already-read pinned code, not a paired repair rerun performed here. [Repair-rerun implementation](https://github.com/LabRAI/ARIA/blob/ce68c040cca0796b37fa8ae46e2a87a073f64001/src/repair/rerun.py).

## Evidence and sources: what each material can answer

Public code and official documentation are inspectable primary materials from their implementers. They are not independent third-party safety validation. The Research Center's probes are internal experiments bounded to extracted functions and synthetic doubles. The layered-audit judgment derived from them is an interpretation.

The [ARIA v1 preprint](https://arxiv.org/html/2610.20780v1) reports repair-data construction and execution checks. Its native backend reconstructs context rather than restoring complete host state. Its repair-success results remain author-reported findings; this article does not turn them into adapter reliability measurements. Publication, citation and revision identity establish provenance and traceability, not general validity. Success in this tested implementation also does not replace independent validation.

The adjacent [probe output](/assets/evidence/2026-11-09-sig-20261109-002/adapter-probe.json) preserves all eight cases, inputs, outputs and the test-double scope. No new model calls, product-instance experiments or external-effect tests were performed for this article.

## Untested hosts and external effects

Eight cases cannot determine whether the real validator always rejects protected substitutions, cover every framework response class, or establish retry, migration or audit completeness. In particular, the permissive mixed-response fixture is not a production exploit: the experiment deliberately removed the lower layer responsible for rejection.

For governed agent adapters, the supported questions are separate: did an intervention change pending text, a host return value or external state? Does its evidence describe a proposal, a delivery or a confirmed effect? Further work requires real hosts combined with the complete controller, plus checks of how unknown provider outcomes are reconciled and authority renewed. The present conclusion ends at the adapter boundary; the unmeasured delivery-and-effect chain remains open.
