# Weekly 001 / 研究周报第 001 期

> **From Agent Frameworks to Governed Digital Employees**  
> **从 Agent 框架走向可治理的数字员工**  
> Observation window: 2026-07-24 — 2026-07-31

## Executive synthesis / 核心综合

The first issue establishes the baseline of the Research Center:

1. interoperability is becoming infrastructure, while governance remains the missing layer;
2. open-source systems are moving from chat agents toward runtime, orchestration and operator control;
3. enterprise vendors are packaging Digital Workforce products rather than generic Agent capability;
4. CodeFlowMu should not become another generic multi-agent framework;
5. the stable product direction is an SME-first Digital Employee Development and Runtime Platform.

首期报告确认：互操作正在成为基础设施，治理成为缺失上层；开源工程正从聊天 Agent 转向 Runtime 与操作控制；企业购买的是岗位化数字劳动力，而不是抽象多 Agent 能力；CodeFlowMu 应收口为面向中小企业的数字员工开发与运行平台。

## Academic signal / 学术信号

### Governance gaps above interoperability

Recent protocol research compares MCP, A2A, ACP and related standards against governance dimensions such as membership, deliberation, dissent, human escalation, audit and replay. The important conclusion for TMPA is layered positioning:

```text
Interoperability protocols
        ↓
TMPA work-data and governance architecture
```

TMPA should not compete as a universal communication protocol. It should govern assignment, evidence, verification, escalation, publication and recovery across different protocols.

### Agent societies and collective governance

Research is moving from single-Agent instruction following toward multi-Agent institutions, negotiation, information asymmetry and collective outcomes. This supports TMPA's focus on responsibility relations and system-level lifecycle control.

## GitHub engineering baseline / GitHub 工程基线

### OpenHands Agent Canvas

The meaningful trend is not one UI feature. OpenHands is moving from a coding Agent toward an operator-facing workspace with skills, plugin visibility, connection health, desktop packaging and automation triggers.

CodeFlowMu should learn:

- connection health and startup visibility;
- skill activation lifecycle;
- operator-facing recovery and diagnostics.

It should not copy generic workspace positioning. Its differentiation is persistent Position, responsibility, evidence and governance.

### AutoGen

Nested teams, shared memory, MCP integration and resumable graph execution are becoming baseline technical primitives. They still do not define organizational ownership, completion evidence or publication authority. CodeFlowMu should remain provider-independent and keep its Position and governance layer stable.

## Enterprise digital workforce / 企业数字劳动力

### ServiceNow

ServiceNow's Autonomous Workforce combines role-defined AI Specialists with deterministic enterprise workflows, escalation and centralized governance. The architectural lesson is that probabilistic intelligence needs deterministic workflow control and explicit authority.

### Workday

Agent System of Record demonstrates the need for a persistent Registry that answers who owns an Agent, what role and skills it has, what it may access, what it costs, and whether it remains compliant.

### Salesforce

Agentforce packages business outcomes by function. Users buy prospecting, service resolution or pipeline work—not “multi-agent capability.” CodeFlowMu should eventually provide executable position packages as well as a builder.

## Impact on TMPA / 对 TMPA 的影响

- keep protocol independence;
- define governance as executable lifecycle control;
- retain SME-first positioning;
- use Digital Employee as the primary application context;
- evaluate evidence, escalation, recovery, human intervention and cost—not only task success.

## Impact on CodeFlowMu / 对 CodeFlowMu 的影响

Recommended positioning:

> **CodeFlowMu is an SME-first Digital Employee Development and Runtime Platform.**  
> **CodeFlowMu 是面向中小企业的数字员工开发与运行平台。**

Initial priorities:

1. Position definition;
2. Digital Employee Registry;
3. workflow and operation-node contracts;
4. runtime observability and recovery;
5. TMPA/FCoP evidence lifecycle;
6. cost and evaluation ledger.
