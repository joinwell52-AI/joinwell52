A1 · 授权不止有token：行动者、人工确认与当前范围 ​

依据：O2 / O4 / O5 / O7 / O18 / O39 / O40。

已有证据：个人OAuth、窄Retry委派、verified provenance和调用前检查分别约束不同事实；MCP新Issue只是开放问题。待验证：人类批准不产生provider原本没有的权限，client accept也不自然证明人类点击。候选实验：准备连接后撤权、成员消息被owner转带、审批后卸载、双租户同名员工；记录何时拒绝与谁承担责任。FCoP可研究授权决定/委派证据引用，凭证签发与执行重检属于Runtime/连接器。代价是身份源和撤权一致性；不直接提出内核改动。互动切入点：被恢复的审批怎样证明仍适用于本轮实际身份？

A2 · 未知结果、已接受报告和新会话不能合成一个成功 ​

依据：O1 / O6 / O14 / O15 / O19 / O20 / O23 / O24。

已有证据：StaffDeck歧义写交人核对，Orca回放已有receipt，Paperclip确认checkpoint丢失后标断续；旧dispatch/interrupt又有独立身份要求。候选实验：外部账本写入后丢响应、报告已收后丢回执、重启换session、旧轮次迟报，分别统计动作/报告/回执/验收；不把新session接着做理解为状态完整恢复。FCoP研究attempt/报告/回执/未知语义，重试/退避/租约留Runtime。需要独立真值与故障注入。互动：无receipt时应保留何种可核验未知状态？

A3 · 任务仍活跃、进程已停止与配置已恢复要独立证明 ​

依据：O9 / O10 / O21 / O25 / O27 / O29 / O31 / O32 / O34 / O44。

已有证据：root/child SessionEnd、后台helpers进程树、MCP共享进程和Git启用状态各有边界。WSL配置策略今天已变，不能照搬昨日结论。候选体验优先固定版StaffDeck和OpenHands，其次Orca跨Windows/WSL迁移，观察正常/崩溃/取消、退出未确认时升级是否停止。共享进程节约资源却增加隔离/所有权代价；进程组、idle、host config属于Runtime，不自动进入FCoP内核。竞品主雷达StaffDeck/Paperclip学习高、Orca第二圈加密专题，不因commit多改称企业成熟。

A5 · 协议互补与开源接入：事件续订不等于永久授权 ​
