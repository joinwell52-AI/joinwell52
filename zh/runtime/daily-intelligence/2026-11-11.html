研究分析 ​

A1 · O3 / O4 / O5 / O6 / O15 / O18 / O26 ​

授权要随执行对象和代际重核，代办权限不必等于接触秘密。证据支持调用前重核、审批归属、秘密单次揭示的不同机制；待验证的是把它们接到 CodeFlowMu 岗位委派与凭据代理后，是否能覆盖跨员工/组织切换。主要落在 Runtime/适配与产品治理层，不直接新增 FCoP 内核规则。实验候选：审批后换身份、移除原 Agent、并发 reveal。互动议题：授权版本变化后，已批准但未执行的动作如何失效？

A2 · O1 / O2 / O8 / O9 / O14 / O17 / O22 ​

协作交付需要区分投递、接受、执行、结果与恢复证据。中断记录不证明副作用未发生；事务回执只在其保护的资源上提供较强恢复依据。待验证：FCoP 工件中的任务/事件/结果语义，能否与 Runtime 的调用身份、回执及 unknown outcome 正确对应；不要把持久化、调度和所有权实现全推给协议。实验候选：执行后掉回执、消息接受后不再推理、损坏事件文件与断连纠偏。
