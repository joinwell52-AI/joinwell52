当日结论 ​

今天最强的共振不是“又多了什么 Agent 功能”，而是 静态配置、历史会话和曾经获得的批准，都越来越不能被当作当前执行权。 MCP 正把服务器发现与实时能力协商拆开；Codex 在权限扩大、插件选择和 AGENTS.md 变化后重新计算有效运行上下文；Superset、Orca 则分别用 workspace-bound token 和 live provider catalog 证明“当前是谁、当前能做什么”。

1. David Soria Parra / Sam Morrow · MCP Server Cards：预连接发现与运行时能力正式拆开 ​

状态：SEP 文本已标记 Final；GitHub PR #2127 仍 OPEN / 未合入。

MCP 的 SEP-2127 在当前提案文本中已标记 Final。该提案由 David Soria Parra、Sam Morrow、Tadas Antanavicius 代表 Server Card Working Group 提出，目标是在建立连接前提供标准化的 HTTP MCP Server discovery。

核心设计包括：Server Card 公开服务器身份、remote endpoint 和 supported protocol versions；域级发现可通过 /.well-known/ai-catalog.json 链接或嵌入卡片；推荐的卡片路径为 <streamable-http-url>/server-card。详细 wire format 由 experimental-ext-server-card 扩展仓库维护。

最重要的边界不是“多一个 discovery 文件”，而是提案明确 不在静态 Server Card 中声明 tools/resources/prompts，也不声明 MCP capabilities/extensions。理由是这些能力可能随 authenticated user、session、配置、feature flag 和 deployment state 变化。连接建立后仍以 live server/discover / 协议协商为权威；若静态卡与实时值冲突，客户端应优先实时值。

为什么重要： 这给 Agent Host 准入一个非常清楚的分层：Discoverable Identity ≠ Runtime Capability ≠ Current Authorization。

与 CodeFlowMu/FCoP 的关系： Host Dependency Center 可以借鉴同一原则：Server/Host Card 负责发现与版本定位；真正准入仍要做 live capability probe、当前身份验证和角色级真实测试，不能把静态声明直接升级成兼容或授权事实。

值得互动：非常高。 技术切入：Would a future Server Card profile expose a stable capability-manifest identity/hash without advertising user-dependent capabilities themselves, so admission can bind discovery to a later live conformance result?

2. OpenAI Codex：权限扩大、插件切换和 AGENTS.md 更新都会使旧运行上下文失效 ​

状态：#44617 MERGED；#44655 MERGED；#44675 MERGED。

Codex 在同一时间窗口连续合入三项很有代表性的边界修复：

  • #44617：一个 exec_command 若请求 with_additional_permissions，不能复用此前只覆盖较窄权限的 Guardian v2 cached approval。现在这种未重新评分的 permission widening 会使缓存分数失效并 fail closed 为 scoring_failure。
  • #44655：thread-level disabled_plugin_ids 现在真正作用到 plugin skills、recommendations、hooks、MCP servers 和 model-visible app tools；插件选择变化只在下一 task 开始时激活，避免 pending settings 改写当前 runtime。MCP tool approval key 也加入 plugin identity，防止不同插件共享一个模糊批准。
  • #44675：长期 root thread 不再永久使用启动时的全局 AGENTS.md。Codex 会在 model-request boundary 重新加载 global instructions，包括同一 turn 的 tool 之后；新 subagent 继承父线程当时已经应用的 instruction snapshot，Guardian reviewer reuse 也会考虑 instruction 已变化这一事实。

为什么重要： 以前的 approval、plugin selection、instruction snapshot 都只是某个上下文下的事实；一旦 effect scope、插件主体或上位指令变化，旧证据不能自动继续授权。

与 CodeFlowMu/FCoP 的关系： 这非常接近 CodeFlowMu 的 Host 插件化和“每次 agent 编程都要看宪法”要求。建议把运行授权绑定到 Policy/Instruction Revision + Plugin Identity + Requested Effect Scope + Authority Epoch，并规定 widening 或 revision change 必须重新裁决。

值得互动：非常高。 技术切入：Do you expect Guardian approval cache keys to converge on one explicit policy-context digest covering effective instructions, plugin identity and normalized permission scope?

3. Superset：Cloud Workspace 从 Blaxel 迁往 Vercel Sandbox；手机 Pages Review 已正式合入 ​

状态：#7408 OPEN；#7367 MERGED。

Superset #7408 是今天竞品侧最值得看的结构性变化之一。由于 Blaxel 被收购，Superset 正把 Cloud Workspace 迁到 Vercel Sandbox，并借迁移重做一部分 Host/Sandbox 信任边界：

  • persistent sandbox 使用 4 小时 session timeout，只有真正打开 workspace 才延长；
  • fork 从已停止 golden snapshot 创建；
  • organization model key 在 egress firewall 注入；若用户为某 provider 配置 personal credential/environment，则抑制该 provider 的组织级 brokered key；
  • Vercel sandbox port 是公开 URL，因此 host-service 成为认证门。API 签发 10 分钟 Ed25519 token，并绑定单一 workspace ID；sandbox 只持公钥；无 token、外 workspace token 或伪造 token 均被拒绝；
  • addressing 与 waking 被明确拆开：查询地址/状态不会唤醒，只有 open workspace 才会启动；snapshot 会终止当前 session 并成为下一次恢复点。

开发分支已经记录真实 Vercel 项目的验证：workspace 约 14 秒 ready，fork 约 6 秒；stop 后 sidebar polling 两分钟不唤醒，重新打开后约 20–30 秒恢复 pane/scrollback；token refresh 连续 35 分钟无 401。但 PR 仍 OPEN，不能当成正式发布能力。

与此同时，此前监测的移动端 #7367 已在 9 月 10 日正式 MERGED：手机端可以浏览 Agent 发布的 Pages，通过 signed viewUrl + WebView 读取，并对页面元素做 comment、quick feedback、thread/pin 等 review 操作。当前 remove/approve 仍以普通评论文本表达，typed intent 还没有完全落地。

为什么重要： Superset 正同时把 Cloud Sandbox 和 Mobile Review 做成产品一等面：电脑负责执行，手机负责看成果和反馈；Cloud Host 则拥有独立 workspace identity 与短时访问凭证。

与 CodeFlowMu/FCoP 的关系： 非常接近“本地/云 Host + 手机审批/证据终端”的数字员工工作站路线。尤其值得借鉴 Address ≠ Wake、workspace-bound bearer、个人凭证覆盖组织 broker，以及手机端只承载 review/control 而非缩小 PC UI。

学习：非常高｜竞争风险：很高｜雷达判断：上调。 建议继续作为“主雷达候选”；若 #7408 合入并完成 production deployment / mobile E2E，可正式升入主雷达。

值得互动：非常高。 技术切入：When a stopped Vercel workspace is reopened, will the new sandbox/process generation be explicitly bound to the previous workspace identity and current credential projection so session continuity cannot imply stale host authority?

4. Paperclip：Board API Key 正从“一个管理员 Token”升级成可审计的最小权限合同 ​

状态：#10972 OPEN；已完成最新 master rebase 与多轮安全验证，但尚未合入。

Paperclip #10972 经过近期重构与安全审查后已经形成相当完整的 board automation authorization contract：

  • versioned scope schema 与 canonical 59-permission vocabulary；
  • 新 board key 不允许 null scope，legacy key 明确标记并暂时保留旧的 unrestricted 行为；
  • 每次请求重新检查 key 与 owner，并把 stored key scope 与 live owner authority 取交集；company access 从 authoritative rows 推导；
  • allow / deny 都写 audit record，mutation 与 audit 耦合，并有 self-revoke 规则；
  • 仓库加入 board-reachable route inventory，新/改 route 如果没有显式声明 policy metadata，CI 直接失败；
  • role demotion、grant provenance、authorization order、audit atomicity 等都有专项测试。

PR 自己也明确保留一个重要限制：PostgreSQL transaction 无法回滚 object store、filesystem、process、provider 或 live publication 等外部副作用，因此这些效果仍需要 durable intent/outbox、稳定 idempotency key、retry state 和 compensation。

为什么重要： 这把“API Key 有权限”进一步拆成 Stored Scope ∩ Current Owner Authority ∩ Current Resource/Route Policy。

与 CodeFlowMu/FCoP 的关系： 对 ADMIN/PM/Host 插件控制很有参考意义：长期凭证不应永久携带创建时权限；角色降级、组织范围变化后，下一次调用必须按当前 authority 重算。

学习：非常高｜竞争风险：很高｜雷达判断：维持 Paperclip 一线 Runtime/控制面竞品。

值得互动：非常高。 技术切入：Will non-database side effects eventually require an authorization receipt that binds the scoped board key, live owner authority, effect precondition and durable outbox/idempotency identity?

5. OpenAI Agents SDK Python：HITL 中断恢复后，未发送的 Tool Output 也必须保持因果完整 ​

状态：#4947 MERGED。

openai-agents-python #4947 修复了一个非常具体但很有架构价值的恢复问题：同一个 model response 可以同时包含一个需要人工批准的 tool call，以及一个调用不存在 tool 的 call。Runner 会先在本地为不存在的工具生成 error output，然后因为另一调用等待 approval 而中断。

此前在 conversation_id、previous_response_id 或 auto_previous_response_id 这类 server-managed continuation 下恢复时，那份已经生成但尚未发送给 Server/Model 的 tool-not-found output 会被误认为已交付，最终造成 server 保留一个 function call 却没有对应 output。新实现以最近一次 model response 的 tool-call IDs 作为中断 turn 的权威集合，同时先识别 server-owned items，保证本地未发 output 被补交，而已经交付的 output 不会重复发送。测试还覆盖了两次分阶段 approval，要求每个 tool output 最终只发送一次。

为什么重要： Resume 不只是“回到某个状态”，还必须保持 Call → Local Result → Delivered Result 的因果完整性和 exactly-once delivery 语义。

与 CodeFlowMu/FCoP 的关系： FCoP/Runtime 中任何 WAIT/HITL/REVIEW 中断都应区分：事实是否已经产生、是否已经持久化、是否已经送达下一主体。三者不能只用一个 Completed 标志代替。

值得互动：高。 技术切入：Would an explicit per-tool effect/result delivery ledger make interrupted-run recovery simpler than reconstructing unsent outputs from the latest model response?

6. Orca：恢复出的 Model 配置不能覆盖 Provider 当前真实能力 ​

状态：#19946 OPEN。

Orca #19946 记录了一个真实 Claude structured-session 故障：session restore 可以重放一个过去有效、现在已被 provider 下架的 model ID；mid-session API（包括 mobile agentSession.setOption）也可以发送任意 ID。Claude Code 的 setModel() 对不存在的 model 仍可能成功返回，但后续每个 turn 都 is_error=true、零 token，使 session 看起来活着却永远没有成果。

候选修复在真正写入 model 前，先读取 live session 自己的 supportedModels() 并拒绝 provider 未列出的 model；restore 遇到 stale choice 则跳过，让 provider 当前 model 保持权威。作者同时明确边界：provider catalog 只能证明 provider 列出该模型，不能证明当前 account/credential 有 entitlement；如果 list_models 根本不可用或为空，为兼容旧 CLI 当前选择不拒绝。

为什么重要： Persisted Configuration ≠ Current Capability。恢复逻辑不能因为“这是上一次保存的配置”就绕过本轮真实 Host/Provider admission。

与 CodeFlowMu/FCoP 的关系： 这正好支持 Host 准入中心的“发现版本 → 采集真实能力 → 与基线差异 → 角色真实测试 → ADMIN adopt”路径。静态 config 和旧 session 都只能是候选输入，不是当前能力事实。

学习：非常高｜竞争风险：中高｜雷达判断：继续提高 Orca 的 Host capability / recovery 权重。

值得互动：高。 技术切入：Would you split provider-listed capability and credential entitlement into two explicit admission facts, so restore can fail closed only when the relevant evidence is actually available?

跨项目共振 ​

今天最值得保留的原则是：

历史可以恢复，身份可以发现，配置可以持久化；但当前执行权只能由当前上下文重新证明。

MCP Server Card 主动拒绝把动态 tools/capabilities 固化进静态发现文档；Codex 在 permission widening、plugin selection 和 instruction revision 变化后让旧批准/上下文失效；Superset 用 workspace-bound token 把公开 sandbox endpoint 收回到具体 workspace；Paperclip 将长期 key scope 与 live owner authority 取交集；Orca 在恢复 model choice 前重新询问 live provider catalog；Agents SDK 则补齐中断前后 tool-result delivery 的因果链。

对 CodeFlowMu/FCoP，可以进一步固定为：

Discovery Identity → Live Capability Evidence → Principal/Scope → Policy Revision → Call-time Authority → Effect/Result Delivery → Replay Eligibility。

这里最关键的是前两项的分离：发现某个 Host/Server/Model 存在，不等于证明它现在对这个账号、这个工作区、这个角色可用。
