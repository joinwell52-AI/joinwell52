# 2026-08-20｜三篇文章事实—主张矩阵

## T1 技能与工具权限

| 类型 | 可写主张 | 证据 | 支持边界 | 反例/未证实 |
|---|---|---|---|---|
| 事实 | MCP 工具可形成任意数据访问与代码执行路径，工具描述不能被默认信任 | MCP Security and Trust & Safety | 支持宿主必须另做授权与控制 | 不代表每个只读工具都必须逐次人工批准 |
| 事实 | NIST 最小权限适用于用户及代表用户的系统进程，并要求限制和记录特权操作 | NIST SP 800-171r3 | 支持角色、权限与日志分离 | 不是 Agent 专用实现方案 |
| 事实 | `SkillContextRouter` 按角色、意图和文本信号选取有限行为手册；常规默认上限为 3 | 实现 + 22/22 测试 | 支持按需加载与调用记录 | 产品设计 Gate 可加载完整必需集合，不可写成永远最多 3 个 |
| 事实 | `RoleToolCapabilityGate` 只检查规范化工具能力，不检查命令内容或效果 | 实现注释 + 测试 | 支持能力门与影响门分开 | 不能把它单独称为完整安全边界 |
| 事实 | `UnifiedOperationPolicy` 根据操作事实只返回 ALLOW 或 REQUIRE_APPROVAL | 实现 + 测试 | 支持操作影响进入独立批准链 | 批准不证明外部执行成功 |
| 事实 | `OperationApprovalService` 记录请求摘要、过期时间、随机一次性令牌与消费状态 | 实现 + 13/13 专项测试 | 支持旧请求失效、超时拒绝和并发单次消费 | 不证明每个工具路径都绑定了 Git HEAD 或文件快照 |
| 事实 | 专用工作区批准适配器可以绑定 Git HEAD 和目标文件快照 | `WorkspaceOperationApproval.ts` | 支持特定工作区操作的前置状态绑定 | 不能外推为所有终端、MCP 与第三方工具统一具备 TOCTOU 防护 |
| 事实 | `MCPInjector` live 模式当前未实现 | 实现 + 22/22 测试 | 必须公开限制 | 不妨碍其他现有 MCP 调用路径，但本文不以动态挂载为卖点 |
| 推断 | 把行为说明、工具能力、操作影响和批准压在一个配置里会扩大越权面 | 上述多源综合 | Research Center 工程判断 | 未做跨框架量化实验 |
| 建议 | 为每次高风险动作保存目标、影响、前置状态、过期时间、一次性消费凭证和批准记录 | CodeFlowMu + NIST/MCP | 可复用设计建议 | 具体字段不是行业标准；仍需操作系统沙箱兜底 |

## T2 项目执行链换根

| 类型 | 可写主张 | 证据 | 支持边界 | 反例/未证实 |
|---|---|---|---|---|
| 事实 | Node 子进程拥有独立 `cwd`，默认继承父进程；不存在的目录会导致 `ENOENT` | Node.js 官方文档 | 支持工作目录必须显式绑定 | 不证明所有外部工具都遵守 Node `cwd` |
| 事实 | VS Code 多根工作区中的未适配扩展可能只使用第一个文件夹 | VS Code 官方文档 | 支持界面包含多个根不等于组件理解多根 | 不直接证明 Cursor 或 CodeFlowMu 行为 |
| 事实 | CodeFlowMu 绑定计划让 Runtime、MCP、watcher 和 Cursor cwd 使用同一活动项目根 | `project-registry.ts` + 27/27 测试 | 支持当前固定提交的同根计划 | 不证明所有第三方 MCP 自己没有缓存旧根 |
| 事实 | `ProjectExecutionContext` 把任务、生命周期和证据根绑定到不可变请求上下文 | 实现 + 测试 | 支持请求内不重新猜根 | 不能替代进程级切换 |
| 事实 | 当前切换路径为紧急取消旧会话、停止 Runtime、持久化新根、应用作用域、重载；持久化失败回滚标识 | `web-panel.ts` | 支持失败关闭、有序重绑定与部分回滚 | 未证明完整优雅排空、Windows 句柄释放或所有外部副作用回滚 |
| 事实 | 当前路径归一化主要使用绝对路径和业务根解析 | `project-registry.ts` + 代码检索 | 支持受测路径的字符串级一致性 | 未找到所有组件统一调用 `fs.realpathSync.native()` 的证据，符号链接别名仍是边界 |
| 事实 | 公开版禁止把自身安装源码根当成开发项目，并拒绝未批准的投影修复 | 实现 + 测试 | 支持安装根保护和不偷偷写目标项目 | 不等于操作系统级沙箱 |
| 推断 | 项目切换应被视为上下文重绑定事务，而不是 UI 状态修改 | 多源综合 | Research Center 工程判断 | 尚无高并发切换基准 |
| 建议 | 切换采用关闭准入、有限排空、句柄探测、超时脏状态、真实路径核对的阶段合同 | Windows/Node 行为 + 实现边界 | 可复用可靠性设计 | 不是当前公开接口已完整实现的流程，也不是 FCoP 字段 |
| 建议 | 切换后以根摘要逐项核对所有组件再恢复任务 | 实现抽象 | 可复用检查表 | 摘要字段是本文建议，不是 FCoP 规范 |

## T3 报告归属与串账

| 类型 | 可写主张 | 证据 | 支持边界 | 反例/未证实 |
|---|---|---|---|---|
| 事实 | W3C Trace Context 用 trace-id 关联跨服务调用链，并用 parent-id 传播调用方当前操作标识 | W3C Recommendation | 支持显式身份和父子关系对关联的重要性 | 追踪关联不证明业务正确性 |
| 事实 | OpenTelemetry 每个 span 最多一个父 span，相关操作共享 TraceId | OTel 官方规范 | 支持因果树需要明确父关系 | span 不是任务报告或验收合同 |
| 事实 | FCoP 把 REPORT 作为独立信封并允许引用任务 | FCoP v3 | 支持协议级外化报告与引用 | 不规定 CodeFlowMu 三字段应用门 |
| 事实 | CodeFlowMu 关键 DEV 回执要求文件名推断、task_id、references[0] 一致 | `reportAttribution.ts` + 44/44 测试 | 支持特定验收硬门 | 不是所有角色/所有报告的通用 FCoP 规则 |
| 事实 | 三字段一致只能排除不一致，不能识别三处同时复制了同一个错误任务号 | 门禁逻辑分析 | 支持静态一致检查的上限 | 当前 44 项测试未覆盖“三处一致地写错” |
| 事实 | 辅助挂树优先显式所有者，但在缺失时也可能使用引用、正文或最近任务 | `reportParenting.ts` + 测试 | 支持界面和账本整理 | 辅助匹配不能冒充确定性业务验收 |
| 事实 | 账本可读取提交轮次、修订与替代关系，汇总门会排除无效或已被替代报告 | `LedgerBuilder.ts`、`PmSummaryGate.ts` | 支持版本裁决的现有构件 | 不证明所有报告写入器都自动分配唯一轮次或完成冲突仲裁 |
| 事实 | QA 缺失/失败、旧报告、归因失败会阻止最终汇总 | `PmSummaryGate.ts` + 44/44 测试 | 支持汇总前的多门条件 | 兼容路径仍可能参考文件时间；时钟漂移未充分验证 |
| 推断 | 展示可以做最佳努力匹配，验收必须在歧义时停止 | 多源综合 | Research Center 工程判断 | 未量化不同启发式的误挂率 |
| 建议 | Agent 只提交正文和证据，由 Runtime 从执行上下文注入所有者、父任务、执行轮次、逻辑事件序号与替代关系 | 实现抽象 + W3C/OTel | 可复用目标设计 | 当前证据不支持写成 CodeFlowMu 全路径已有能力；字段组合不是行业统一标准 |
