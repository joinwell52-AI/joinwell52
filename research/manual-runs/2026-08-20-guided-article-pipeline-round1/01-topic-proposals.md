## 题目一

### 《AI Agent 的技能不是工具权限：为什么“会怎么做”和“允许做什么”必须分开？》

**写给谁：** 正在给 Agent 接入技能、MCP 工具、终端和外部服务的架构师与工具链工程师。

**文章要解决什么：** 防止 Agent 因为读到了某份操作手册，就把“知道怎样做”误当成“有权执行”；同时避免把所有技能和工具常驻在上下文中。

**读完得到的结果：** 一张“方法—工具—权限—批准”四层架构图、一份技能接入审查表、三个可直接落成自动化测试的越权案例。

**大纲：**

1. Agent 读到了发布手册，是否就等于它可以发布？
2. 拆开四件事：行为手册、工具注册、角色能力、具体操作批准。
3. 为什么把所有技能塞进提示词既浪费上下文又放大误触发。
4. 怎样按角色和任务只加载少量行为手册，并留下调用记录。
5. 为什么工具名获准仍不代表任意参数和副作用都获准。
6. 同一个写文件工具，写项目内文件与逃出项目根为什么必须得到不同裁决。
7. FCoP、CodeFlowMu 与 TMPA 分别负责协议声明、运行时强制和治理边界。
8. 三个必测越权案例与一份四层审查清单。

**与近 30 天内容的区别：** 8 月 2 日文章讲技能、插件与契约的行业趋势；本题讲我们已经实现的四层分离和具体越权门禁，不是旧文换标题。

## 题目二

### 《切换项目后，Agent 为什么还在改旧目录？一条执行链怎样安全换根》

**写给谁：** 在一个本地 Agent 应用里管理多个代码库、工作区或客户项目的 Runtime 与 IDE 工程师。

**文章要解决什么：** 界面显示项目 B，但 Runtime、MCP、文件监听器或 Agent 工作目录仍有一处指向项目 A，最终读错任务、改错代码、写错报告。

**读完得到的结果：** 一张项目切换时序图、一份七项同根不变量表，以及防止 Agent 修改旧项目的验收步骤。

**大纲：**

1. 车祸现场：页面显示项目 B，补丁却写进项目 A。
2. 为什么项目切换不是修改一个下拉框或全局变量。
3. 必须同时换根的七个对象：Runtime、MCP、Watcher、Agent 工作目录、任务、生命周期、证据。
4. 安全顺序：停止旧会话→停止旧 Runtime→持久化新根→应用作用域→重载并核对。
5. 请求级不可变项目上下文怎样避免各组件重新猜根。
6. 目标目录消失、会话无法停止、注册表写入失败时怎样回滚。
7. 为什么切换时不应偷偷修复或重写目标项目的协议目录。
8. 四类回归测试和七项同根检查表。

**与近 30 天内容的区别：** 站内近 30 天没有以多项目切换的同根绑定事务为核心的文章；它也不是昨日故障注入文章的泛化复述。

## 题目三

### 《AI 团队同时交回三份报告，怎样保证验收没有串账？》

**写给谁：** 让开发、测试和运维 Agent 并行工作的技术负责人、平台工程师和 PM。

**文章要解决什么：** 多份报告同时出现时，系统只按时间、线程或正文相似度挂账，导致一份报告归到错误任务，错误解锁依赖或生成错误最终总结。

**读完得到的结果：** 一套报告身份证设计、一张归属决策树、四个串账反例，以及最终汇总前的核验清单。

**大纲：**

1. 一个事故：开发、测试、运维三份报告都在同一线程，最终总结却引用错任务。
2. 为什么“时间最近”“正文相似”“同一线程”都不足以证明归属。
3. 报告的几张身份证：文件身份、任务编号、父任务和引用。
4. 关键验收回执为什么必须核对文件名推断、显式任务编号和首个任务引用。
5. 展示路由可以辅助匹配，验收门禁为什么不能在歧义中猜。
6. 返工、同线程多个根任务和旧报告怎样避免抢走新任务归属。
7. 为什么没有诊断、Agent 自称完成或报告存在都不能代替 QA 通过。
8. 四个回归测试和最终汇总前检查清单。

**与近 30 天内容的区别：** 8 月 6 日文章讲“完成声明为什么没被放行”；本题只讲并行报告如何准确挂到任务、怎样防止验收串账，证据对象和读者行动不同。

## 本轮建议

建议三个都保留。它们分别回答：

1. Agent **能做什么、能不能做**；
2. Agent **到底在哪个项目里做**；
3. Agent **做完后的证据到底属于哪项工作**。

三篇形成一条完整但不重复的工程链：**执行权边界 → 执行上下文边界 → 交付证据边界**。
