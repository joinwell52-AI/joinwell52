# 一句话能否变成授权：2026-11-17 有界研究

## 来源与研究问题

今日情报收集了 44 项事实观察、6 项分析。我们优先检验 A1“消息来源不能升级为执行授权”，并用 A4“产出不等于验收”作相邻边界对照。其余 A2、A3、A5、A6 保留为观察或后续实验，不能计作已完成实验。

直接触发源是 [Orca #43093](https://github.com/stablyai/orca/pull/43093)：贡献者报告真实 Codex 运行曾把 Agent 消息中的授权说法当成人的批准，从而放行有风险的上传。该 PR 的修复把消息作为指针，审批留在本地 UI。这个事故与修复是 Orca 的第一方记录，不是我们在 CodeFlowMu 复现的事故。相邻对照是 [ADK Python #8185](https://github.com/google/adk-python/pull/8185)：子 Agent 的输出出现在事件中，却未进入父 Agent 的输出上下文；该 PR 截至本次核对仍开放。它提示“存在一份内容”和“有权的接收者完成处理”应分开核验。

本地问题：**AI 员工转述“用户批准了”或把完成状态写绿，能否在受测入口获得执行或验收资格？**

## 固定对象、方法与结果

- 本地对象：CodeFlowMu V3.0.152，提交 `0d2d4e742ef2f3cb48e3ce09cc47f0c03053dc5f`；受测真实模块为 `OperationApprovalService.prepare` 与 `AcceptanceFactProjection.acceptanceFactFromTask`。
- 在独立临时项目中创建合成外部写入请求，固定项目、任务、目标分支与动作。只变更请求发起者、确认来源、确认 ID、核验器或目标分支；观察审批判定、持久审批记录数量及 `executed` 标志。
- 另构造根任务及正式验收决定，分别变更报告状态、旧式文本转换、决定中的责任人和任务 ID；观察验收事实投影。
- 探针只调用当前产品模块，没有执行 `git push` 或任何外部副作用。确认核验器是实验注入的；当前生产构造路径并未注入该核验器，因此“有效 UI 确认放行”一行只证明接口合同，不能宣称生产 UI 已接通该直通路径。

## 机制解释与边界

准备阶段计算操作摘要；对外部写入，普通 Agent 请求需要形成审批。直通确认还要同时满足“用户发起、受信 UI 来源、非空确认 ID、核验器认可当前操作摘要”。更换目标使摘要改变，因此旧确认不能在本探针中放行新请求。根任务的 `done` 只是内容状态，正式验收投影要求匹配任务、角色、责任人的注册决定。

可以把本次受测关系写成：

```text
消息中出现“批准”  ≠  执行授权
受测直通条件 = 用户发起 ∧ 受信 UI 来源 ∧ 有确认 ID ∧ 核验器认可当前操作摘要
准备阶段 ALLOW ≠ 外部操作已执行
报告 done ≠ 根任务正式验收
```

这组结果说明当前受测接口没有让转述文本直接变成授权，也没有让根任务状态词直接变成验收。它没有检验完整 Host、真实用户界面、恢复后的会话、独立接收者或真实外部服务。下一轮最有价值的是在原生操作门禁与真实 UI 确认路径上，分别比较“批准后换参数”“批准后换执行者”“批准后恢复会话”，并让独立验收者读取同一份工件版本。
