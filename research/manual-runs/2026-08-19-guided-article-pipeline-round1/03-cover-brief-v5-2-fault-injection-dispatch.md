# Cover Brief V5｜重复通知只产生一次 Agent 派发

- itemId：2026-08-19-fault-injection-dispatch-v5
- 文章：别被“全绿演示”骗了：怎样用故障注入，测出一个真正靠谱的 AI Agent 调度系统？
- 唯一视觉命题：故障注入器故意复制同一任务通知；两条相同信号同时进入调度核心，但最终只有一次有效派发进入 Agent，重复信号被拦下并留下证据。
- 中心主体：一个紧凑、透明、具有状态记忆的 AI 调度核心。
- 唯一动作：左侧任务信号被复制成两条相同通知，同时进入核心；核心完成防重复裁决。
- 可见结果：右侧只有一条派发进入一个计算 Agent；另一条通知停留在核心内部的隔离区，可供检查。
- Agent 形态：由代码流、模型会话与执行脉冲组成的单一计算实体，不采用机械机器人外观。
- 构图：16:9，严格沿一条水平轴组织；左侧双输入、中央调度核心、右侧单输出，三者紧密相连，背景大面积明亮留白。
- 文字规则：只允许三个准确短标签：`TASK 001`、`DUPLICATE`、`1 DISPATCH`。
- 视觉风格：明亮、未来、富有创造力；暖白空间，钴蓝任务信号，透明青色调度核心，琥珀色重复证据与单次派发脉冲。
- 为什么这样做：它用文章中的具体故障场景表达测试方法——允许重复观察，但不能产生第二次业务派发；比抽象爆炸或多重轨道更能说明 Agent 调度可靠性。
