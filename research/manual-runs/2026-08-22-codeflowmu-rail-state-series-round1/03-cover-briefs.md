## V1 — 多个 Agent 怎样真正组成团队？治理模型、文件状态机与工程轨道机

- **核心命题**：多个 Agent 成为团队，不靠同时运行，而靠共同的治理语义、可检查的文件状态和负责执行/恢复的工程轨道连成一条责任链。
- **读者第一眼应认出**：一束密集需求与证据正在被收束为一张统一、可追踪的数字任务图。
- **关键动作**：信息流进入一个紧密咬合的中央数字计划，分配到互锁模块后形成一条稳定责任路径。
- **前后差异**：左侧是未组织的输入；中央之后是一个稳定、连续且可归属的任务链。
- **不可删除锚点**：同一中央主体内的互锁任务模块与从中穿出的单一责任路径。
- **最危险误读**：被看成普通数据流、消费电子广告或多屏仪表盘，而不是“长输入被治理约束成可交付团队任务”。
- **一个视觉句子**：一束需求与证据流进入一张互锁的数字责任计划，离开时成为一条可追踪的稳定任务路径。
- **主体与权重**：中央数字计划约占画面 70%；输入流细且收束；输出路径更细、更稳定；紫色证据锚点仅作辅助。
- **颜色语义**：青蓝 = 正常任务与状态链；紫 = 证据；少量暖琥珀 = 模块咬合处的受约束交接。
- **构图/材质/光线**：16:9，明亮象牙白未来空间；中心偏右但占据画面视觉中心；透明陶瓷、光学玻璃与精密数据纹理；柔和高亮与清晰边缘；所有表面无文字。
- **拟输出**：`03-visuals/cover-team-governance-state-rail-v1.png`。

## V2 — 任务怎样在 Agent 团队中流转？文件状态机如何记录领取、执行、审查与完成

- **核心命题**：文件路径保存当前阶段，追加事件保存历史；出现双阶段或重复领取时，系统必须保留冲突并停止猜测。
- **读者第一眼应认出**：同一个任务身份穿过一个巨大的状态机核心；正常路径连贯，故障分支被单独保留而非伪装成完成。
- **关键动作**：一个任务身份在中央状态核心中迁移；一条琥珀色异常分支被隔离到对账位置。
- **前后差异**：正常青蓝路径连续通过；异常不继续派发，保持可见、可对账。
- **不可删除锚点**：中央状态核心中的一条主路径和一条颜色持续一致的隔离异常分支。
- **最危险误读**：被看成游乐设施、抽象交通图或泛网络节点，掩盖了“当前状态与历史事件分离”的主题。
- **一个视觉句子**：同一任务在中央状态核心中沿青蓝路径稳定迁移，一条琥珀色重复分支被清楚留在对账边界。
- **主体与权重**：中央状态核心约占画面 75%；任务身份和小型证据结构从属；异常分支不能大过主体。
- **颜色语义**：青蓝 = 当前合法迁移；琥珀 = 重复/冲突且未裁决；紫 = 可独立核查的证据。
- **构图/材质/光线**：16:9；一个大型、紧凑的透明计算状态体位于中央，直线/短曲线迁移轨迹，右侧小型证据环；明亮雾白与浅银背景，晶体/光学玻璃质感，表面无文字。
- **拟输出**：`03-visuals/cover-task-file-state-machine-v1.png`。

### V2-R1 — 用户指出“第二张图不清楚”后的语义重构

- **问题诊断**：原 V2 只画出抽象状态核心与支路；读者无法第一眼认出“同一任务工件”及其跨阶段流转。
- **重构动作**：用一个中心任务文档穿过四个连续、紧密连接的阶段槽位，取代抽象方形核心；上方只保留一个琥珀色重复文档作为对账锚点。
- **一个视觉句子**：同一任务文档沿四个连续的文件阶段前进，重复副本被单独留下对账，而不进入前进路径。

## V3 — 轨道机怎样带动一支 Agent 团队？派工、恢复与人工裁决的工程边界

- **核心命题**：轨道机可以派工、保存技术事实和恢复可确认步骤，但不能把不确定事实或业务判断伪装成自动结论。
- **读者第一眼应认出**：一个中央计算轨道核心持续带动正常任务；一枚不确定决定被清楚送到核心外的授权位置，而没有被核心吞没。
- **关键动作**：青蓝任务令牌穿过中央计算轨道；琥珀色不确定令牌向上离开执行路径，抵达独立的决定锚点。
- **前后差异**：确定的技术动作继续向前；业务判断被保留给独立的决定者。
- **不可删除锚点**：中心计算轨道与位于其外、由琥珀路径连接的单一决定锚点。
- **最危险误读**：被看成火车轨道、纯自动化装置或“系统替人下决定”的宣传图。
- **一个视觉句子**：中央计算轨道推进可确认的任务，同时把一枚不确定决定送到轨道之外的独立授权锚点。
- **主体与权重**：中央计算轨道约占画面 70%；决定锚点明显较小但清楚可见；青蓝执行路径与琥珀决定路径不交叉。
- **颜色语义**：青蓝 = 可确认的执行/恢复；琥珀 = 需要授权的决定；紫 = 被保留的核查事实。
- **构图/材质/光线**：16:9；单一大型竖向或斜向计算核心，紧密的状态单元形成一个整体；上方一枚小型琥珀授权印记；明亮白金未来空间，半透明陶瓷与发光数据结构，表面无文字。
- **拟输出**：`03-visuals/cover-rail-assistance-boundary-v1.png`。
