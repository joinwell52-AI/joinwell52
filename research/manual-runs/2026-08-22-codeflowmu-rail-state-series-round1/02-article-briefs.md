# Article Briefs

## T1｜多个 Agent 怎样真正组成团队？治理模型、文件状态机与工程轨道机

- **目标读者：** 已经能调用多个模型或 Agent，但还没有稳定协作治理层的架构师与平台工程师。
- **痛点：** 多个会话都会执行和汇报，却没有稳定任务身份、共享状态事实、独立验收和可恢复责任链。
- **核心问题：** TMPA、FCoP、CodeFlowMu 如何分工，又如何连接？
- **唯一主张：** 团队化的关键不是增加 Agent 数量，而是把治理语义、状态事实与运行执行分层，并让三层通过稳定身份和证据引用连接。
- **原创价值：** 首次用当前 V1.9.7 事实内核解释三层如何进入同一端到端协作链，而不是分别介绍三个项目。
- **文章类型：** 架构解释 + 工程案例。
- **论证节点：** 失败场景 → TMPA 定法理 → FCoP 保存状态 → CodeFlowMu 运行轨道 → 一次完整协作 → 反例与边界 → 自查表。
- **代码需求：** `RailAssistanceResult` 字段节选；不得公开大段私有实现。
- **图示需求：** 内容批准后再制作三层责任图；正文阶段仅保留文本图占位概念。
- **风险：** 容易把 TMPA 写成产品、FCoP 写成调度器、V1.9.7 写成正式发布。
- **读后行动：** 为自己的系统画三层责任图，逐项指出谁拥有事实、执行和最终决定。
- **与系列区别：** T1 讲分层关系，不展开每个状态迁移，也不集中讨论轨道越权。
- **证据判定：** PASS。
## T2｜任务怎样在 Agent 团队中流转？文件状态机如何记录领取、执行、审查与完成

- **目标读者：** 实现本地多 Agent 任务调度、证据归属和验收的工程师。
- **痛点：** 文件正文写着 done、任务仍在 active、报告已经出现、人工尚未验收时，系统容易选择最方便的信号继续执行。
- **核心问题：** 一张任务怎样保持唯一身份，并在状态、历史、报告和验收四个层面合法流转？
- **唯一主张：** 当前状态、迁移历史、执行回执和验收决定必须分账；状态机提供可观察事实，轨道机只机械连接它们。
- **原创价值：** 从 V1.9.7 命令合同和防重复实现出发，串联 FCoP 当前状态机，而不是重复协议字段说明。
- **文章类型：** 机制型技术文章。
- **论证节点：** 冲突信号 → 四类事实 → 文件迁移 → 命令身份 → 依赖与防重复 → 报告与验收 → 局限 → 不变量清单。
- **代码需求：** `canonicalThreadKey()` 与任务命令字段的短摘录；其余使用明确标注的结构示意。
- **图示需求：** 内容批准后制作任务四事实流转图。
- **风险：** 原子 rename 被夸大成事务或分布式一致性；`review/` 目录与 `REVIEW-*` 混淆。
- **读后行动：** 给自己的任务系统增加五组不变量测试。
- **与系列区别：** T2 只追踪一张任务的生命史，不讨论完整三层定位和轨道治理哲学。
- **证据判定：** PASS。

## T3｜轨道机怎样带动一支 Agent 团队？派工、恢复与人工裁决的工程边界

- **目标读者：** 构建 Agent Runtime、控制面与自动恢复机制的技术负责人。
- **痛点：** 分类器、完整性检查、重试次数和超时容易被实现成隐性业务否决，最终由轨道机替 PM 判断任务该不该继续。
- **核心问题：** 哪些事情轨道可以自动做，哪些判断必须留给 Agent、PM 或 ADMIN？
- **唯一主张：** 轨道机应自动处理可复核的机械事实与技术恢复，但业务范围、验收、返工和最终报告必须由有权主体决定。
- **原创价值：** 以 V1.9.7 的真实修复和冻结负面清单，给出可复用的“辅助—裁决”分界方法。
- **文章类型：** 工程判断 + 版本案例。
- **论证节点：** 两种失败 → 边界原则 → 辅助合同 → 负面清单 → 派工/恢复职责 → 人工决定 → 测试证据 → 残余风险 → 审计表。
- **代码需求：** `RailAssistanceDisposition`、`decision_owner` 和 `business_decision: null` 的短摘录。
- **图示需求：** 内容批准后制作轨道辅助与裁决分界图。
- **风险：** 把第一方回归写成独立证明；把候选版本写成 RELEASED；把负面清单写成完整安全模型。
- **读后行动：** 把现有自动化规则分类为事实、建议、机械拒绝和业务决定，删除越权路径。
- **与系列区别：** T3 关注自动化权力边界，不重复 T1 的三层入门和 T2 的完整任务生命周期。
- **证据判定：** PASS。
