# 用户反馈返工记录｜Round 3

日期：2026-08-23。本文档记录用户建议作为编辑方向后的核验与处理，不把建议本身当作事实来源。

## T1｜三层责任与工程轨道机

| 反馈方向 | 核验结果 | 正文处理 |
|---|---|---|
| CSV 例子的生命周期缺少 `inbox → active → review` 动作 | 成立。FCoP 当前规范指定 `claim_task` 与 `submit_task` 的显式 L1 迁移；REPORT 不自动搬动 TASK。 | 阶段表扩展为创建、领取并绑定、执行、提交并进入审查、验收；明确每次迁移的调用者与事件。 |
| 单写者需要说明文件并发写与 rename | 方向成立；“按 Agent 子目录、无需锁、物理杜绝冲突”未获当前规范支持。FCoP 只承诺同边界的 write-then-rename，且多主机并发需要外部一致性层。 | 增加 REPORT/REVIEW 独立工件与 TASK 迁移竞争的区分；说明双领取和跨主机场景不被 rename 自动解决。 |
| `unknown_reconcile` 应说明语义 | 成立，但自动熔断/通知/回滚未获证。 | 增加四种 disposition 的有界解释：对账不等于裁决；机械暂停只来自显式依赖或冻结负面条件。 |
| 私有 Runtime 与外部复现存在落差 | 成立。TMPA S1.0 有公开符合性工件，但其范围不等于 V1.9.7 私有轨道机。 | 将下一步验证拆为公开治理/协议语义轨和获准访问的私有运行时轨。 |

## T2｜任务状态机

| 反馈方向 | 核验结果 | 正文处理 |
|---|---|---|
| 崩溃后 `inbox/` 与 `active/` 同时存在时按迁移事件选最新状态 | 不成立。FCoP 规定路径是 NOW，事件是 PAST，禁止从事件导出当前状态。 | 明确双阶段副本是冲突：Reader 保留并报告，停止投影单一状态；后续由受权生命周期动作恢复或清理。 |
| 说明 `expected_revision` 的产生方式 | 当前证据只证明其被绑定和检查，未公开生成算法。 | 写成当前版本前置条件令牌，并明确不能声称是 hash、单调计数或 mtime；给出变化后重放旧令牌的验证方法。 |
| Dispatcher 需要 DAG 环检测 | 作为工程建议成立；当前材料仅证明显式依赖等待与释放，未证明已实现环检测。 | 标记为待补的派工器测试合同，不冒充当前功能。 |

## T3｜轨道辅助边界

| 反馈方向 | 核验结果 | 正文处理 |
|---|---|---|
| `unknown_reconcile` 应自动冻结并切换 PM/ADMIN | 自动冻结与自动通知未获证，且当前合同只允许显式依赖/冻结负面清单机械暂停。 | 明确它首先是对账处置；若要停止高风险动作，必须有 TASK 前置条件、冻结规则或 PM/ADMIN 显式决定。 |
| 工具权限应按任务阶段动态收缩 | 是值得增加的工程策略；当前 V1.9.7 检查角色、能力、作用域与修订，但未证明所有工具按阶段动态收缩。 | 作为需增加的策略与测试，明确不写成已完成能力。 |
| 超时应产生技术诊断与人类接管选项 | 技术语义方向成立；当前证据支持托管作业的日志、有限等待、授权取消，不支持全会话心跳、自动诊断或 PM 推送。 | 将超时写为技术事实和后续策略，而非自动业务失败或已实现的通知流程。 |

## 对全局标准的候选经验

本轮再次验证四条可迁移经验：

1. 生命周期表必须列出显式迁移工具、触发者与状态位置；不能用“报告生成”暗示状态已迁移。
2. 路径事实与事件历史不可互相替代；双路径存在时先保留冲突，不能根据事件挑选“最新状态”。
3. 枚举名、接口字段和建议架构不构成自动化行为证据；必须写清当前合同是否定义暂停、通知、回滚或恢复。
4. 私有产品的可验证范围必须拆成公开规范/符合性验证与受限产品验证，不能把前者冒充后者。
