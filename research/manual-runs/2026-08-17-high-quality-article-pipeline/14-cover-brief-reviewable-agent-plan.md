## 内容锚点

- 核心问题：为什么 Agent 在大型任务中需要先计划，但计划又不能取代原始需求？
- 核心命题：计划是可审查、可修订的派生工件，不是权威需求；执行前必须把计划重新对齐需求、代码事实与验证方式。
- 原创机制：authority inversion——看似正式的计划获得过高权威，导致下游忠实执行一个错误中间层。
- 读者行动：使用六段 Plan Contract，在批准前检查需求映射、代码位置、依赖风险、验证、非目标与执行偏差。

## 视觉锚点

- 一个占据画面中心的未来 Agent 执行核心，形态是精密、自主、非人形的机械/光学装置。
- Agent 核心正准备进入下方一整块深色代码实体；两者组成一个集中、稳定的主结构。
- 执行核心与代码实体之间只有一张大型透明计划校准片，由实体机械框架固定。
- 一枚厚重、明亮的原始需求基准石与校准片同轴；一道清晰光路先对齐基准石，再穿过计划片进入代码实体。
- 计划片内部可见一条轻微偏移、随后被校准回正的路径，表达“计划可错、必须审查”，而不是把计划画成权威终点。

## 构图与质感

- 元素集中在画面中央 55% 区域，形成单一主视觉，不做散点信息图。
- 低机位三分之四视角；前景为代码实体边缘，中景为计划校准片与 Agent 核心，背景只提供克制的未来实验室纵深。
- 材质采用深色钛金属、烟灰玻璃、冷白与琥珀校准光；具有可信机械结构与编辑摄影质感。
- 高对比但不追求霓虹炫技；缩小到约 320px 宽时仍能看清 Agent 核心、计划片、需求锚点和单一光路。
