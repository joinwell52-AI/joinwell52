## 逐条事实核验

### 2. E2EDevBench 样本、模型与工作流

- **通过。** 论文从 2024-Q1 至 2025-Q1 每季度随机抽取 10 个合规 PyPI 项目，共 50 个 Python 项目。Table 1 报告平均 19.2 个源文件、2011.5 LOC、119.7 个测试；中英文候选均一致。
- **通过。** 三类工作流为 SDAgent-Single、SDAgent-DT、SDAgent-DDT，均构建在统一 SWE-Agent 基础和工具链上，采用顺序 handoff；底座模型为 Gemini-2.5-Pro 与 Gemini-2.5-Flash。候选没有把结果泛化到其他模型或真实企业大仓库。
- **通过。** 论文的主指标 Impl-Rate 是三次 judge 一致判为 implemented 的需求占全部需求的比例；分母还包括一致判为 not implemented 以及三次判断不一致的需求。候选写成“需求实现率”没有错，并已说明评估依赖 Test Migration Agent 和 LLM judge。
- **通过。** 53.50% 是 SDAgent-DT + Gemini-2.5-Pro 这一最佳单一配置的 Impl-Rate。
- **通过。** 49.48%、45.72%、27.71% 分别是 Table 3 中 SDAgent-DT、SDAgent-Single、SDAgent-DDT 的 Mean 行，即对 Pro 与 Flash 两个模型行求得的工作流均值；不是三个工作流之间的总体平均，也不是可直接外推的行业成功率。候选的“Averaged by workflow / 在三种工作流的均值中”语义基本正确。
- **通过。** 55.8% 的分母是从 50 个项目、Pro 模型、三类工作流的未实现需求中随机抽取的 1,000 条，而不是全部 Agent 失败。55.8% 下分为需求遗漏 27.9%、需求误解 22.2%、架构设计错误 5.6%；Task Execution 38.6%，Task Verification 5.7%。候选完整保留了该限定并明确禁止泛化。

### 3. 坏计划机制与替代解释

- **通过。** 论文在 §4.2 使用 “we hypothesize / we attribute” 描述 DDT 机制：Developer 可能把 Design Agent 产出的 blueprint 当成权威实施计划，从而优先于原始需求；这不是独立随机化计划质量后的因果识别。
- **通过。** 中英文候选分别写成“论文作者检查轨迹后提出一个解释”和 “the authors propose a mechanism”，随后明确说这是作者解释而非因果实验。
- **通过。** 两篇都保留了额外 handoff、上下文压缩、workflow prompt 可能解释部分差异，未把 DDT 与 DT 的差距单因归因给“坏计划”。

### 4. Higher-Order Work 观察研究

- **通过。** 本地 79 页论文与 SSRN 元数据一致：总样本为 1,000 家企业、119,960 名匹配到职业特征的用户；消息意图数据覆盖 399 家企业。
- **通过。** Table 8 的无条件 Plan rate 常数为 4.21%；工作经验增加 1 个标准差（论文注明约 7 年）与 Plan rate 增加 0.45 个百分点相关，论文解释为相对基准约高 11%。
- **通过。** 候选明确称其为观察研究，指出低 R²、任务选择混杂、意图分类器未报告独立人工准确率，并没有写成“计划导致更好输出”。
- **精度提醒。** 119,960 是总体职业特征样本，不是 Table 8 的消息意图回归人数。Table A2 给出的意图子样本为 42,348 名用户、399 家企业；Table 8 为 118,407 个 user-week observations。现有分号写法没有直接造错，但发布前若补上这一层，会让分母更难被误读。

### 5. Plan Contract 的证据身份

- **通过。** 六段合同不是任何单一来源的既有 schema。两篇在结尾都明确写成由产品机制、受控实验和观察研究综合出的建议，并说明尚无独立实验测量这套结构在真实大仓库中能降低多少遗漏。

## 修改建议

### 建议 1：把 E2EDevBench 的均值和分母再说准一层

可将相关句调整为：

> 最佳单一配置 Developer-Tester + Pro 的需求实现率为 53.50%。Table 3 对 Pro 与 Flash 两行求得的工作流均值分别是：Developer-Tester 49.48%、Single 45.72%、Designer-Developer-Tester 27.71%。这里的实现率按逐需求三次 judge 一致判定计算，分母包含未实现与判断不一致的需求。

英文同步表达即可。这样能彻底消除把 49.48/45.72/27.71 误读为全样本 pooled rate 的可能。

### 建议 2：补充消息意图子样本人数或观测单位

可把“消息意图子样本覆盖 399 家企业”扩为“消息意图子样本覆盖 399 家企业、42,348 名用户；Table 8 使用 118,407 个 user-week observations”。这不是纠错，而是让 119,960 总样本与实际回归分母不混在同一句中。

### 建议 3：把结尾的规范性判断与因果证据再分开

把“证据已经足以排除两个极端”改为“证据边界与已观察到的机制风险共同支持避免两个极端”，能与前文对因果性的谨慎程度完全一致。

### 建议 4：为 SSRN 增加备用直达链接

SSRN 短链接对自动访问返回 403。建议在来源列表保留 SSRN landing page，并补作者 PDF 或 DOI，提升读者可达性和后续复核稳定性。
