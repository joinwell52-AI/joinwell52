## 1. Material change / 实质变化

PyOD `v3.6.5` is not a documentation-only release. Relative to the previous P2 checkpoint at `v3.6.4`, it changes benchmark-data generation and detector behavior in ways that can alter anomaly-evaluation results.

The highest-value change is in `generate_data`. In `v3.6.4`, the synthetic generator sampled its internal `offset_` with:

```python
offset_ = random_state.randint(low=offset)
```

With the default `offset=10`, this draw can be zero. `_generate_data` then creates outliers from `uniform(-offset_, offset_)`; when `offset_ == 0`, every labelled outlier collapses exactly to the origin and has zero variance. The release notes report that 46 of 501 integer seeds in the tested range 0–500 produced this degenerate outlier block, and that KNN reached ROC AUC 0.0 for several affected seeds.

`v3.6.5` redraws only the zero-offset branch, rejects offsets below 1, handles float offsets in `(1, 2)`, and adds regression tests that explicitly sweep formerly failing seeds and require non-zero outlier spread. The release also fixes ROD behavior at the geometric median and restores CBLOF's estimator parameter contract, but those are secondary to this study's benchmark-validity question.

## 4. Mechanism analysis and minimal reproduction / 机制分析与最小复现

The failure is a data-validity failure before it is a detector failure:

```text
seed
  ↓
randint(0, offset)
  ↓
offset_ == 0
  ↓
uniform(-0, 0)
  ↓
all labelled outliers == 0
  ↓
synthetic ground truth no longer represents intended outlierness
  ↓
detector metric can measure generator pathology rather than detector quality
```

A minimal independent reproduction was performed from the `v3.6.4` source mechanism using the same NumPy/Scikit-learn random-state semantics. For seeds `0..500`, with default `offset=10`, 46 seeds produced `offset_ == 0` and therefore a zero-variance outlier block. The reproduced set includes the release-noted seeds `41`, `48`, `50`, and `85`.

Reproduction result:

```text
seeds checked:              501
degenerate outlier seeds:    46
rate:                      9.18%
release examples present:  41, 48, 50, 85
```

This independently confirms the core generator pathology. It does not independently reproduce every detector metric in the release, which is not required to establish the benchmark-validity mechanism.

## 5. Independent external judgment / 独立外部判断

Before mapping this result to any JoinWell52 project, the general engineering judgment is:

> **A benchmark score is only as trustworthy as the mechanism that generated and labelled the evaluation sample. Synthetic anomaly benchmarks need explicit dataset-validity invariants before detector metrics are admitted as evidence.**

The important design lesson is not "use PyOD" or "avoid PyOD". It is to separate three propositions:

1. **Generator validity:** does the sample actually contain the anomaly structure its labels claim?
2. **Metric validity:** does the metric measure the behavior we care about under that sample?
3. **Operational relevance:** does that sample resemble the online process where the detector will run?

A high detector score does not establish (1) or (3), and a generator defect can make (2) meaningless.

## 6. Bounded first-party relevance / 与第一方项目的有边界关联

### CodeFlowMu / Digital Employee

If future CodeFlowMu monitoring uses anomaly detection over Agent events—tool-call frequency, failure bursts, lifecycle timing, delegation depth, permission denials, or recovery anomalies—its evaluation harness should add **dataset sanity gates** before model scoring. Examples include non-zero variance for intended anomaly groups, separability/centrality sanity checks where applicable, label prevalence checks, and seed-sweep stability.

This report does **not** authorize adding PyOD to CodeFlowMu, changing Runtime policy, or treating anomaly scores as governance decisions.

### TMPA / Research Operating System

The evidence model should distinguish `benchmark-generated evidence` from `validated benchmark evidence`. A benchmark artifact can be reproducible yet systematically malformed for a subset of seeds. Evaluation reports should therefore preserve generator version, seed, parameterization, dataset sanity results and detector version as part of provenance.

### FCoP

No FCoP protocol change is justified by this repository release alone. At most, the study supports the general principle that machine-produced evidence needs explicit validation before becoming an authoritative REVIEW fact.

## 7. Action / 行动建议

**Experiment Candidate.** Run a bounded first-party experiment before any product mapping:

1. Define one synthetic Agent-runtime event schema with known injected anomalies.
2. Generate multiple seeds and retain generator identity, seed and parameters.
3. Apply dataset-validity invariants before detector scoring.
4. Compare detector metrics with and without the validity gate.
5. Fail the experiment if anomaly labels can collapse into non-anomalous structure without the gate detecting it.

No public article is created by this P2 run, and no first-party implementation is authorized.
