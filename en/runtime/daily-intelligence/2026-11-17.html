2026-11-17 Agent Research and Competitive Intelligence ​

The highest-priority research questions are preventing agent messages from impersonating human authority; distinguishing returned Stop/timeout from stopped effects; and distinguishing child output from delivery and acceptance by its parent. Orca, Codex, OpenHands, Paperclip and ADK supply concrete fixes or open counterexamples. The AAE A2A-extension discussion adds request binding and accepted-but-failed versus rejected-and-not-invoked semantics, still an open proposal.

Research analysis ​

A1 Priority research: message provenance must not become execution authority ​

Evidence：O1、O2、O3、O4、O5、O10、O14、O18、O19、O38、O39、O44。

Supported: Orca, OpenHands, Agents SDK and GitHub MCP distinguish agent mail, synthetic goals, human decisions and exact-request acceptance; Codex adds evidence cutoffs. Enterprise governance needs provenance and the specific approved action beyond allow/deny. Persistent repository trust is a different tradeoff. Unverified locally: collapsing employee delegation, comments and human approval into user text in an adapter could lose authority boundaries. P0 experiment candidate: drive one harmless test upload via agent mail, system notice and explicit human approval, then vary expiry, changed parameters and revocation. Assert effects and decision binding, not a reviewer’s safe label. Compare sender/delegation/evidence expression at FCoP; identity, current permissions and enforcement belong to Runtime/adapters. Costs include identity, digest and authorization-version management and possible human delay. Interaction topic: prevent an old quoted human authorization from being reused for a new action.

A2 Priority research: verify stop, timeout, takeover and settlement separately ​

Evidence：O5、O6、O8、O9、O13、O22、O23、O24、O25、O29、O31、O33、O40。

Supported: timely CrewAI TimeoutError does not kill a running thread; Paperclip distinguishes stop request, handoff, no-start proof and settlement; Paradev generation guards prevent stale stop writes. Caller return and execution termination need separate evidence, without implying every framework has the same fault. P0 experiment candidate: interrupt a uniquely identified countable local action before preparation, after handoff, after effect but before receipt, during controller restart, and with a late old terminal event; also transfer timed-out work to a backup employee. Measure duplicates, orphan processes, unsettled receipts, latency and manual ambiguity. Define thresholds before execution. FCoP can compare task/event/result/evidence contracts; leases, owner generations, retries and process termination belong to Runtime. Costs include fault injection and retained uncertainty. Interaction topic: what evidence permits recovery when a tool received the action but its outcome is unknown?

A3 Audit must explain omissions, corrections, aggregation and history windows ​

Evidence：O1、O7、O11、O12、O15、O32、O34、O35、O36、O37、O41、O42。

Supported: logging alone is insufficient. OpenHands appends corrections, Langfuse retains object sets/stable IDs when aggregating, Phoenix exposes both missing and unintended telemetry, and Kyvvu states a bounded history window. Unverified locally: final-only employee summaries could hide failed cost, policy-window limits and evidence gaps. P1 experiment candidate: inject a malformed span, redacted correction, secret read crossing the history window, 1,000-object batch, failed-model usage and concurrent trajectory writes. Verify original provenance, explainable edits, complete sets and explicit loss counts. auditable 0.5 is a candidate for stage-aware comparisons, not a combined safety guarantee. FCoP can compare evidence/correction semantics; collection, storage, export access and retention are Runtime/operations. Costs involve privacy, indexing and storage. Interaction topic: prove aggregate object completeness without re-recording sensitive values.

A4 Priority research: completion requires delivered and consumed results ​

Evidence：O6、O9、O13、O14、O16、O25、O30、O33、O44。

Supported: ADK child output in an event stream need not reach parent context; coalesced Paperclip wakes must retain child-completion reasons; Codex acceptance is not wakeup. Distinguish acceptance, execution, artifact production, handoff, parent consumption and independent acceptance. P0 experiment candidate: a research→synthesis→independent-review three-role flow with reordered artifacts/messages, duplicates, paused parents and children completed before resume. Verify the right artifact versions reach parent context and incomplete delivery can be rejected by the reviewer. Compare FCoP semantics with A2A task/artifact/authorization outcomes and AAE request_digest; MCP readiness/skill catalogs are complementary integration, not automatically same-layer competitors. AAE cross-run counts remain participant claims requiring independent recomputation and separate wire tests. Costs include version/consumption tracking; no FCoP core change is yet established. Interaction topic: route child artifacts arriving after parent cancellation to history, reopen, or independent acceptance?

FCoP can compare artifact/version declarations; installation, dependencies, sandboxing, credentials and rollback belong to Runtime/product delivery. Costs include compatibility, storage, OS permission differences and failed-update fallback. Interaction topic: make the shift from approved bytes to future repository content visible and revocable.
