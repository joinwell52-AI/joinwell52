Agent Research & Competitor Intelligence · 2026-09-16 ​

Asia/Shanghai · Only meaningful technical or product developments are included.

Back to the daily archive

Daily conclusion ​

The strongest convergence today is that the current execution context of a long-running Agent is becoming something that must be proven independently. Model quota, executor host, sandbox policy, plugin authority, guardrail outcome, credentials, workspace location, and mobile request generation can no longer be assumed valid merely because the Session or history still exists.

1. Yue Zhao / anywhere-agents: quota routing becomes live resource balancing, while completed reviews survive late 503s only under explicit recovery evidence ​

Status: COMMITTED TO MAIN / COMMITTED TO MAIN

Yue Zhao personally landed two meaningful runtime-governance changes in anywhere-agents.

The first is 91c64c1. A 198-unit prun batch on September 15 consumed 77 percentage points of the Agy Gemini five-hour meter in 63 minutes while the second Agy quota group—claude-sonnet-4-6, claude-opus-4-6-thinking, and gpt-oss-120b-medium—sat unused. Unpinned units now read both quota groups before dispatch and may route to the group with more headroom when the lead is at least 15 points and the destination has positive evidence for both metered windows. Each unit decides independently, so a batch can shift groups as headroom changes. The runtime records MODEL-BALANCE plus the actual model used. Explicitly pinned models do not participate in this balancing policy.

The second is a566f92. Four /vet Agy reviews on September 15 had already produced complete review text in their final result events, but a later UNAVAILABLE 503 made the terminal status ERROR, and the old dispatcher discarded all four. Recovery now publishes only a result that carries the current round marker, a standalone Verification status, and a commit verdict outside closed code blocks. It also persists backend-failure; Health Check 8 must warn, and the coordinator still inspects the recovered review for placeholders, narration, or truncated findings before accepting it.

Why it matters: two common binary assumptions are being decomposed. Quota is becoming time-sensitive resource evidence rather than available/unavailable, and process terminal status is no longer treated as identical to work completeness. A complete artifact can exist before a late infrastructure error, but the error must remain visible and trigger re-verification.

CodeFlowMu/FCoP relevance: models can be scheduled as role resources, but routing should retain the quota snapshot, actual model, and balance/fallback reason. Runtime should also separate Provider Terminal Status → Work Artifact → Verification Verdict rather than letting any layer stand in for final acceptance.

Interaction value: very high. Suggested question: Would you bind quota-snapshot age/source, the actual model, backend terminal status, recovery warning, and final verifier verdict into one dispatch receipt?

2. OpenAI Codex: Thread/Turn state is being bound to executor host, sandbox policy, plugin authority, and recovery evidence—not just conversation history ​

Status: MERGED TO MAIN

Codex landed a cluster of mutually reinforcing runtime changes today:

  • #45813 brings Windows sandbox policy and per-thread executor-host classification into the TUI. Reported environments are classified as local / remote / mixed / unknown across start, resume, fork, and replay, while setup must satisfy both configuration and managed requirements.
  • #45812 adds workspace routing for Responses requests. HTTP/WebSocket backend origin, account routing, and credential revision participate in connection identity; routed requests reject redirects, refresh request setup after credential renewal, and reject account changes during setup or routing discovery.
  • #45807 expands managed-daemon recovery snapshots beyond thread IDs to include active uncanceled turn IDs and turn-specific options such as output schema, service tier, and cyber access program.
  • #45806 restricts plugin-install requests to the root thread; subagents are rejected before argument parsing or install elicitation.
  • #45789 / #45782 preserve Guardian user restrictions and verified answers across model switches, compaction, restart, and checkpoint migration. When reviewer/checkpoint compatibility is unknown or mismatched, legacy evidence is retained instead of silently promoting an incompatible checkpoint into new authority.

Why it matters: long-lived thread continuity is being decomposed into Conversation Identity, Turn Identity, Executor Host, Sandbox Policy, Plugin Authority, Authorization Evidence, and Recovery Generation. Being able to resume a thread is no longer evidence that the current execution context is equivalent to the old one.

CodeFlowMu/FCoP relevance: after multi-host moves, room rebinding, or model changes, recovery should bind an explicit execution-context digest instead of inferring authority from the UI session. Formal PM/DEV/QA/EVAL boundaries should also keep internal subagents from installing plugins or expanding host capability.

Interaction value: very high. Suggested question: Will these per-thread/per-turn facts converge into a unified execution-context digest that binds host/sandbox, plugin authority, policy evidence, and recovery generation?

3. OpenAI Agents JS: guardrails, tool sets, and MCP credentials increasingly require the current context to still be valid ​

Status: MERGED TO MAIN

Several governance-oriented fixes landed in openai-agents-js today:

  • #1938: if the output-guardrail batch itself errors, the final assistant output is considered unvetted even when no guardrail explicitly returns a tripwire. It is withheld from Session history and cannot re-enter the model through later replay. The user input may remain, and transaction-aware Sessions can preserve tool-call/result pairs whose effects are already known.
  • #1937: computer safety-check rejection blocks the corresponding action without unnecessarily aborting the whole Run.
  • #1931: an explicit empty tool list on a Realtime transition now has real semantics; stale tools from the previous Agent are cleared instead of surviving inheritance logic.
  • #1933: MCP credentials are redacted before crossing into AI SDK/browser UI output.
  • #1932: current MCP tool filters are re-applied even when discovery is cached; historical discovery does not keep a tool visible after the current policy changes.

Why it matters: a guardrail that did not finish, an Agent that currently has no tools, or a filter that has changed cannot be overridden by stale Session state. History proves what existed before, not what still has display, invocation, or inheritance authority now.

CodeFlowMu/FCoP relevance: incomplete EVAL/review should remain uncertain/unverified rather than allowing the model's final prose into the formal fact chain. Role/Agent transitions should recompute tool capability and credential projection from the current role.

Interaction value: high. Suggested question: Will effective tool set, credential projection, and guardrail-completion identity become part of a Session generation so resume/replay cannot inherit stale capability?

4. Paperclip: durable sandbox artifact delivery lands while ACPX is found persisting Run credentials in plaintext Session records ​

Status: #13493 MERGED; #13498 OPEN

Paperclip #13493 has merged. Legacy sandbox bridges previously rejected attachment listing, while the queue bridge correctly carried only JSON/UTF-8, so PNG/PDF binary outputs could not be published reliably; the native runner also needed a consistent durable registration path. Legacy and native paths can now complete attachment listing/upload/download, work-product registration, and response binding. Queue envelopes support bounded base64 bodies while retaining multipart headers, stable retry identities, and uncertain-write semantics. Live Daytona verification covered PNG/PDF bytes, Unicode filenames, duplicate registration, authorization controls, and byte-for-byte downloads after sandbox deletion. New outputs surface in the task Artifacts UI.

The same day, security PR #13498 exposed a more serious boundary: the ACPX Session Store persists the whole session_options.env into <stateDir>/sessions/*.json, including API keys/tokens bound to the current Run. On a single-host deployment, multiple seats use the same OS account, so filesystem permissions do not isolate seats. Codex paths may also duplicate the environment through $CODEX_HOME/shell_snapshots/*.sh. The proposed fix strips launch env on save() and re-injects the current Run's environment on load(), while disabling shell snapshots in managed Codex homes. Focused 195 tests pass, but the PR remains OPEN and must not be treated as shipped.

Why it matters: Session persistence should preserve how to continue a conversation, not freeze a reusable copy of old credentials. A Workspace/Session may be durable; credentials belong to the current Run/Principal and should be projected again at resume time.

CodeFlowMu/FCoP relevance: multi-role and multi-host design should enforce Session State ≠ Credential State. Digital Employee rooms, profiles, and tasks can persist, but secrets should be dynamically injected from the current authority generation and should not appear in durable Session records.

Learning: very high | Competitive risk: very high | Radar: Paperclip remains at the highest priority; add Session-at-rest secret exposure and durable artifact delivery as dedicated dimensions.

Interaction value: very high. Suggested question: Will Paperclip move toward an explicit allowlist contract for persistable Session fields and bind credential reinjection to the Run principal/authority epoch instead of relying on field scrubbing?

5. Paperclip: a blocked recovery state is being required to name an executable unblock owner ​

Status: OPEN

PR #13494 comes from a real recovery defect. Four escalation paths could set an Issue to blocked while providing neither blockedByIssueIds nor an unblockDescriptor. The Issue then looked formally blocked but appeared in no executable owner queue and had no wake path, effectively becoming permanently invisible.

The proposed fix requires that, when no first-class blocker relation exists, the same state write also creates a board-owned unblockDescriptor. Reusing the assignee Agent as the unblock owner would be wrong because these paths often exist precisely because the assignee has no invokable execution path. Provider-quota waits or Issues with real blocker relations do not get a redundant descriptor. The project explicitly notes that this PR closes the generator of orphan blocked states but does not yet implement a global blocked && no blocker && no unblock owner invariant detector.

Why it matters: Blocked cannot be only a status color. A recoverable block must answer who unblocks it, under what condition, and who is woken afterward. Otherwise the track machine merely turns a runtime problem into a state that nobody owns.

CodeFlowMu/FCoP relevance: this directly maps to QA chasing, clearing “waiting for QA receipt,” and one-click deadlock recovery. A useful contract is Block Cause + Unblock Owner + Unblock Condition + Wake Target; without these, a TASK should not be materialized as a recoverable Blocked state.

Learning: very high | Competitive risk: high | Radar: keep Paperclip first-line and raise Recovery ownership weight.

Interaction value: high. Suggested question: Will you add a board-level invariant so every blocked Issue must prove either a blocker relation or a typed unblock owner at commit time?

6. Superset: Cloud Workspace is moving from an optional place to a first-class CLI/MCP/SDK location semantic, with conservative fallback for non-cloud accounts ​

Status: MERGED TO MAIN; Cloud behavior remains capability/feature-gated

Superset #7564 has merged. For accounts that can use Cloud Workspaces, workspace list/get/open/update/delete, terminal operations, and agent creation can treat Cloud as the default when no location is specified; --local and --host make local or named-host execution explicit. Accounts without Cloud capability, offline clients, or clients talking to an older API that cannot answer the capability query conservatively keep the original local behavior rather than accidentally starting a billed sandbox.

The shift goes beyond CLI flags. MCP folds cloud-specific workspace tools into the unified workspace surface; the SDK is narrowed into a cloud workspace/terminal/agent control plane; Cloud Workspaces take their repositories from Environments. At the same time, reading a running Cloud Workspace no longer wakes it on every call: clients try a 0600 local cached ticket, then mint a no-wake ticket against the stored address, and wake only when the sandbox is actually stopped or unreachable. A mutation that may already have reached host-service is not automatically replayed after wake/reconnect.

Why it matters: Superset is making Workspace Location a first-class product abstraction: Cloud, Local, and Named Host become locations behind a shared Workspace API. It also recognizes that a cloud default can create a real billing side effect, so uncertain capability falls back locally rather than guessing.

CodeFlowMu/FCoP relevance: multi-host CodeFlowMu can similarly separate Workspace Identity from Execution Location. Default routing should be a provable capability/authorization decision, and “read the address” should remain distinct from “wake the machine.”

Learning: very high | Competitive risk: very high | Radar: Superset is already a primary-radar competitor; add Workspace Location semantics, no-wake access, and billed-default guards as dedicated dimensions.

Interaction value: very high. Suggested question: Will workspace location/default route become a durable scope bound to account-capability revision and Host identity so the same CLI/MCP command cannot silently move execution after account or plan changes?

7. Orca: mobile RPC begins using generation leases to own cache, in-flight requests, and stale-result publication authority ​

Status: OPEN

PR #20914 is Step 5 of Orca's mobile RPC foundation. GenerationScopedRequestOwner centralizes generation refs, cache, in-flight maps, and stale-response decisions that had been scattered through hooks. read/load take a scope made from authority epoch, workspace identity, and parameters; encountering a new scope retires old state before answering. Only a module-private lease minted by the owner can commit(value), and commit is refused after the generation moves.

It explicitly handles A→B→A. Even if the visible scope eventually looks identical again, reset() still advances the generation, so a delayed response from the first A cannot regain publication authority in the second A. Tests cover reset, blur, cutover, reconnect-mid-request, and stale in-flight cleanup. The project also states that mobile does not yet have a real negotiated capability epoch, so it does not invent one merely to satisfy the abstraction; existing host/workspace identity latches remain the real evidence.

Why it matters: seeing the same parameters again does not mean the request belongs to the same authority generation. Old results may arrive late, but equal keys must not let them overwrite new state.

CodeFlowMu/FCoP relevance: multi-host rooms, resume, dashboards, and mobile control can use the same principle: Generation is an authority boundary, not a cache optimization. After Reset/Rebind/Host change, an old request may remain evidence but cannot overwrite the new generation's facts.

Learning: very high | Competitive risk: medium-high | Radar: further raise Orca's Mobile RPC / authority-generation weight.

Interaction value: very high. Suggested question: Will the generation lease expand into a shared authority epoch across RPC, terminals, notifications, and recovery rather than remaining a mobile request-cache primitive?

Cross-project convergence ​

The day's cross-project direction can be reduced to one sentence:

Persist the fact chain, not old authority; recover context, not old execution rights.

Independent projects are reaching the same conclusion from different sides. Zhao turns live quota snapshots into pre-dispatch evidence. Codex carries host/sandbox/plugin/evidence into Thread/Turn recovery. Agents JS requires current guardrails and tool filters to still hold. Paperclip lets artifacts outlive sandboxes while stripping credentials out of Session records. Superset makes workspace location explicit execution semantics. Orca rejects stale results using generation leases.

A useful CodeFlowMu/FCoP chain is therefore:

Work/Run Identity → Current Generation → Principal/Credential Projection → Workspace/Host Identity → Live Capability/Capacity Evidence → Call-time Authority → Effect/Artifact → Verification/Settlement

Generation should become a real recovery and authority barrier: Sessions, caches, provider conversations, and historical results may remain as evidence across generations, but they should not automatically carry authority across that boundary.
